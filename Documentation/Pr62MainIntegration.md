# PR #62と最新mainの統合

対象ブランチは `codex/steering-warning-fair-items`、統合前の先端は `3611bfe`。

まずmain `0d6ec99` の夜景・UI・起動保護と統合した。競合したチューブ制御は、加速パネル・回転矢印を維持し、mainの `DriverNoticeSignal` へ加速成功を一度だけ送る形で合わせた。UI側の代替通知経路でも成功の優先度を維持する。3つのHUDフォントはどちらかの旧アトラスへ戻さず、統合後の文言から410文字を生成した。夜景のコース、表示解像度制御、タイトル・ゲーム・結果の排他表示はmainを保持する。

検証中にmainへ追加された `45e9e07` までの更新も取り込んだ。ダッシュボード操作の返却と非同期プレビュー、壁走行時のカメラ、チューブ模様、結果のNextから個別エンディングへ進む動作、メンテナンス音楽を維持する。

## 検証

- Core：182件成功。Unity EditMode：182件成功。
- 旧・新HUDの接続：加速成功がmainの通知キューへ成功優先度で届き、消費後に毎フレーム再表示されない。旧チャージ報酬を復活させない。
- 実画像のチュートリアル：全4ページ×2人×720p/1080pの写真、文字欠け・はみ出し・入力透過・独立した完了条件を確認。
- ハンドル警告とアイテム：両プレイヤー・2解像度で検証。最後尾の保護と前方への対象選択を維持。
- 夜景・走行：本番車両の高速コーナー31条件、急ハンドル86条件、チューブの滑らかな面・入口・出口の接続を確認。
- タイトル：通常初期化とGmanager初期化前の障害を想定した2ケースで、ゲーム・結果が重ならず、起動例外なし。
- メンテナンス：実際の7段階と3画面、物理・時間・通常音声の停止、再開と再起動を確認。追加された保守BGMは両プレイヤーで橘諸兄をループし、通常音声だけが停止を維持することも検証。
- 実走チュートリアル：加速・操舵・実アイテム取得から説明ページとカウントダウンまで成功。P2のアイテムまで65.4m、接近2.5秒。
- 自動復帰8条件：乗り上げ、塞がれた復帰先、実際の着地失敗位置、通常ジャンプを確認。
- `0d6ec99`との統合状態で前進のみ・手動リセットなしの追加レースを実走。意図的な壁向き操舵後も2人とも2周完走し、周回取りこぼしと走行記録中の実行時エラーは0。
- `45e9e07`まで含む最終状態でも画面・通知・チュートリアル・物理の統合検証と、運営機能・保守・EditMode検証を実施。ダッシュボードは稼働中サービスと分けたポートと一時コピーで検証する。

結果は `Artifacts/RacePolishMainIntegration/`。再実行の入口は `RacePolishMainIntegrationValidation.Run`（同期検証）、`RunOperations`（運営のPlay検証）、既存の `ScreenStartupValidation`・`MaintenanceModeValidation`・`ForwardOnlyRecoveryValidation`・`BalancePlaytestValidation`。

最初の別作業場所はLFSアセットがポインタのままだったため展開した。コピー由来のEditor検索索引も作成し直し、起動試験は例外を除外せず成功させた。いずれも元の作業場所を変更していない。Unityが書き換えた一時的なマテリアル・再撮影画像は統合コミットへ混ぜず、mainの正式な更新を保持する。

運営プレビューのバッチ検証では、両画面をRenderTextureに描画して10回の非同期コピー・HUD寸法不変・Nextの独立動作を確認する。通常の対話実行ではP1の実画面キャプチャ経路を維持する。Unityのバッチモードは `WaitForEndOfFrame` を実行しないため、検証側だけを分岐した（[Unity公式資料](https://docs.unity3d.com/ja/2023.2/Manual/CLIBatchmodeCoroutines.html)）。実画面のキャプチャ経路は今回再検証していない。

Windows実機、ESP32実機、物理的な音声出力機器による確認は未実施。
