# 個別スタート・チューブ補助・ゴール後の音楽・結果タイマー

タイトルの開始操作は操作した本人だけをチュートリアルへ進める。相手は自分が操作するまでタイトルに残る。最初の開始からレース開始までは従来どおり最大60秒。共通の準備期限では、未開始側の練習を始めず、直接カウントダウンへ進める。2人目の開始操作は共通の時計や1人目の練習をリセットしない。管理画面の全員開始操作は引き続き両方を開始する。

チューブでは2輪以上の接地を必要とし、現在の接地面へ投影したコースの進行方向へ穏やかに補正する。床、斜めの壁、垂直壁、天井に対応する。車体を平らな道路へ戻す力や姿勢変更は加えない。強いハンドル操作を優先し、アシストOFF、切断、空中、復帰中、入力を妨げるアイテムの状態では補正しない。

ゴール曲はプレイヤーごとに先頭から1回だけ再生する。曲が終わると、相手が走行中なら相手の通常／最終周BGMの再生位置に合流する。両者の走行終了後は結果曲へ進む。結果画面への遷移だけでは曲を再スタートしない。ゴール曲の途中で結果画面になった場合は、その1回を終えてから結果曲へ移る。DNFではゴール曲を鳴らさず結果曲へ進む。

**新しいゴール音源は添付待ち。現時点では既存のfinishv4を保持している。** 曲の長さは読み込んだAudioClipのサンプル数から求めるため、新音源にも同じ1回再生の処理を適用できる。

結果画面右下に残り15秒のカウントダウンを追加。表示と退出案内への移行はGmanagerの同じ時計を使い、画面遷移中・メンテナンス中は進めない。次へ操作による早送りは維持する。

第3画面はP1/P2と共通の枠なし全画面ウィンドウ配置を使用する。内蔵画面を優先し、ない場合はCoreGraphicsのメイン画面を使用する。P1へフォーカスしたことで別の画面へ出すことを避ける。起動時のウィンドウ作成失敗は1秒後に再試行する。手動の移動・リサイズ・閉じる操作は自動で取り消さない。別アプリに切り替えると中継は隠れ、戻ると再表示する。

## 検証

- 共通ロジック196件成功。
- Unity 6000.3.9f1のCore・本体・Editorアセンブリをコンパイル。開いているEditorでもアセットを更新し、検証メニューを実行。
- `PlayerAudioValidation.Run`: 1回再生、観戦対象の曲への合流、結果曲の継続、各画面の独立性、タイトル復帰・次レースでの再設定を確認。
- `PlayerStartTubeResultValidation.Run`: 本番の個別開始を2人分実行し、相手待機・重複操作・時計の保持を確認。本番の接地判定と操舵補助で床／±45度／±90度／天井を確認。両方の結果配色、カウント値、文字・配置、実際のGmanagerの14秒・15秒境界も確認。
- `Native~/RaceWindows/test.sh`: 画面選択とAppKitの全画面ウィンドウ配置を検証。テスト用ウィンドウは一度も表示せず、実行中のRACEには接続・入力・終了・再起動を行っていない。
- ネイティブプラグインをarm64/x86_64で再ビルドし、公開シンボルの互換性を確認。既存プロセスが読み込んだファイルを上書きせず、リポジトリのファイルだけを原子的に置き換えた。新しいゲーム全体のビルド・起動は行っていない。

描画と検証結果は`Artifacts/PlayerStartTubeResult`に保存。元からあったSampleSceneの編集は保持し、コミット対象から除外する。
