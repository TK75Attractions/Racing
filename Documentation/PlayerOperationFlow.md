# プレイヤー別の入力・結果表示と運営ホーム（2026-10-31）

P1・P2の自動運転を、それぞれ管理画面のゲーム設定とF8から切り替えられる。両者自動のテストレースも同じ二つのスイッチを使う。片側をOFFにすると、その車が保持している元の入力ソースへ戻り、ペダルを一度離してからESP32の操作で走行を再開できる。入力モード設定を切り替えたり、シリアルポートを開き直したりする必要はない。自動運転を一度でも使用した走行は、本日の順位には登録しない。タイトルに戻って次の参加者を受け入れるときは、両者の自動運転をOFFに戻す。再レースでは現在のスイッチ設定を維持する。

従来の両者自動モードは、個別スイッチとは別のフラグが自動運転を強制していた。このため個別にOFFにしても手動へ戻らなかった。現在は両者自動かどうかを二つのスイッチから判定する。

タイトル・車選択・結果・「ありがとうございました」の決定は、ペダルを踏んだまま画面へ入っても受け付ける。画面ごとの長押し時間は維持し、画面の切り替え中は加算しない。結果は従来の入力待機時間の後から長押しを計測する。練習も最初のペダル解放を待たずに走り始められるが、加速課題の完了には実際の車速が必要。コース説明は踏み続けていても最低4秒を表示してから先へ進み、入力がなくても8秒で終了する。

`PedalRelease` の解放帯域（絶対値20％以下）は走行中の再接続、自動運転からの手動復帰、遠隔操作からの復帰などで使う。これらの走行再開時の確認は残す。タイトルや結果などの画面上の決定操作には使わない。

「ありがとうございました」は画面変更とレースの破棄時に、表示と完了コールバックの両方を解除する。管理画面の「もう一度」から開始した新しいレースを、前の終了画面や自動復帰処理が覆わない。

管理画面ホームには、機器の接続、確認が必要な事項、P1/P2それぞれのコース復帰ボタン、ハンドル角度、独立したアクセル・ブレーキの入力値を表示する。復帰は遠隔操作の引き受けなしで使用できる。通信切断、閲覧専用、復帰できないゲーム段階では無効になる。入力表示には実機から受信した値を使い、古い受信記録を現在の正常な入力と区別する。

## 通常／クイックの選択

管理画面の「ゲーム設定 → ゲームの種類」で切り替える。通常は練習あり・2周、クイックは練習なし・1周。クイックでは片方の開始操作後はその画面を準備完了とし、両者が開始すると練習・説明・コース紹介を省略してカウントダウンへ進む。最初の開始操作で試合のルールを固定し、その後の変更は次の参加者から適用する。ゲームの種類はアプリ終了まで保持する。

## ゴール後の画面

各プレイヤーのゴール演出が終わると、その人の結果を表示する。相手は自分の画面で走行を続けられる。結果の表示時間は各画面で15秒を計測し、「次へ」の操作も個別に受け付ける。

結果を見終えた時点で相手がまだ走行している場合だけ観戦へ切り替え、中央に「相手のゴールを待っています」と表示する。相手が完走またはタイムアウトしたら待機表示を終える。すでに結果を見終えた人には同じ結果を再表示せず、終了画面へ進める。相手のゴール時にまだ結果を見ている人は、自分の残り表示時間を維持する。未完走の人はレース終了後にDNFの結果を表示する。

結果の本日順位では「N位」を大きく、参加人数を小さく表示し、その日の同じコース・周回数・進行方向のベスト合計タイムも併記する。上位20％の枠は人数の20％を切り上げ、少人数の場合は最低1位を対象にする。同タイムは同順位として扱い、金色の紙吹雪と順位のパルス演出を表示する。CPU、自動運転、未完走などの対象外条件は維持する。

## 周回判定の仕組み

現在はチェックポイント用の物理センサーを順番に踏む方式ではなく、コース中心線上の距離と、仮想ゲートで判定する。`LapManager.OnCarPassCheckpoint` は互換用に残っているが、周回を進める処理は行わない。

1. スタート位置と向きから、進行方向と1周の基準距離を決める。車の位置をコース上の距離へ変換する。
2. 1周を16分割した位置にある15個の仮想ゲートを、正しい順番で通過したことを記録する。正方向の走行距離を加算し、逆走分は差し引く。
3. 全ゲートを通り、正味で1周の90％以上を走ると周回完了の候補になる。道路・走行可能な路肩・チューブ内など、正規の走行領域にいるときだけ有効な進捗を加算する。
4. 進捗がコース終端から先頭へ正方向に跨いだことを、物理更新でも検出する。車の速度がコース進行方向へ出ていることも確認し、1周を加算する。通常は2周でゴールとなる。

スタートラインの直後で前後に往復しても、仮想ゲートと必要な走行距離が揃わないので周回にならない。瞬間移動やコース外へのショートカットは、距離・位置の連続性チェックで進捗に加算しない。復帰では観測の基準位置を更新し、飛び越えた区間を走ったことにはしない。スタートラインより後ろのグリッドから最初にラインを越える短い助走も、1周として数えない。

実装は `Assets/Managers/LapManager.cs` と `Assets/Managers/Multiplayer/Core/LapTraversal.cs`。高速走行で細いゴール用トリガーを飛び越えても、コース距離の跨ぎを検出できる。

## 検証

- `Tools/Validate-Rgp.sh`：コア、シリアルプロトコル、個別自動運転設定、アナログ解放値、ランキング、周回の回帰テスト。
- `node --test Tests~/Dashboard/*.test.cjs`：管理画面の入力表示・復帰権限・切断・プレイヤー別結果表示を含む回帰テスト。任意の診断ブラウザーテストは通常実行ではスキップする。
- `PlayerOperationFlowValidation.Run`：本番のシーン・車両・入力ゲート・画面遷移をPlayモードで検証する。実機の代わりに差し替え可能な入力ソースを使い、P1/P2の自動OFF、保持ペダルと再接続、練習の解放、両側の先着、僅差、観戦、DNF、表示中の終了画面からの再レースを確認する。
- 同じ検証から `DailyRankingValidation.Run` を実行し、日付の切り替え、保存失敗、対象外条件、P1/P2の720p・1080p描画も確認する。結果・観戦画面の画像は、テスト実行先の `Artifacts/PlayerOperationFlow` に保存する。

開いているUnityとは別の一時コピーで実行し、運営中のシーンや本日の実記録にはテスト結果を保存しない。実物のESP32・ペダルを接続した手動操作は未検証。
