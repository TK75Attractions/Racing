# プレイヤー別BGM・効果音・USB/HDMI音声出力

ゲームはP1/P2それぞれに独立したステレオ音声を、別々のUSB/HDMI音声機器へ送ります。OSで認識される出力機器を2台接続してください。ディスプレイの割り当てと音声機器の割り当ては別です。

## 曲と視点

- 通常走行・カウントダウン: `Assets/Resources/Audio/BGM/racegame_v3.mp3`
- 最終周: `Assets/Resources/Audio/BGM/racegame_v3_final lap.mp3`
- ホーム（タイトル）〜車選択: `Assets/Resources/Audio/BGM/Race_Opening_v2.mp3`
- チュートリアル: 既存の `Assets/Resources/Audio/BGM/TachibanaMoroe.mp3`（橘諸兄）
- ゴール後・ウイニングラン・リザルト: `Assets/Resources/Audio/BGM/finish_v2.mp3`

完了周回数が `Goal Lap - 1` になると、そのプレイヤーのBGMだけをFinal Lap曲の先頭から再生します。1周レースではスタートからFinal Lap曲です。ゴール時に本人の曲だけをfinish曲の先頭へ切り替え、その後の観戦・リザルトでも継続します。未完走で観戦に入った場合は観戦対象の周回曲に合わせます。タイトルへ戻った画面はopening曲へ戻し、もう一方のリザルト曲は維持します。準備中も各画面の進行に合わせ、片方が車選択、もう片方がチュートリアルならそれぞれの曲を再生します。各曲はループ再生します。エンジン音は各画面の実際のカメラ座標から車両までの距離と左右方向で音量・ステレオ定位を計算します。近くの相手車も聞こえ、80m以上離れると聞こえなくなります。

エンジンは6速ATに連動する4気筒合成音です。トンネルでは車両ごとの反響も独立出力へ送ります。仕様・試聴サンプル・検証方法は [EngineAudio.md](EngineAudio.md) を参照してください。

## 出力先の設定

1. OSの音声設定でUSB/HDMI出力機器が認識されていることを確認してゲームを起動します。
2. 初回は列挙された1台目をP1へ割り当てます。P2は設定から出力機器を選択してください。
3. レース中にESCでメニューを開き、`設定` の `P1 出力` / `P2 出力` ドロップダウンから機器名を選びます。両画面のメニューから設定できます。一覧には `出力なし` と、相手が使用していない出力機器が表示されます。
4. 同じ機器を両プレイヤーへ同時に割り当てることはできません。割り当てを交換する場合は、片方を一旦 `出力なし` にしてからもう片方を変更します。
5. 変更はOSの機器IDで保存され、次回起動時に復元します。USBの抜き差し後は `再検出` を押してください。保存された機器がない場合、そのプレイヤーの音声を停止して未接続と表示します。

Master/BGM/エンジン音/効果音のスライダーは両プレイヤー共通です。BGMを0にしても効果音は鳴り、効果音を0にしてもBGMは鳴ります。Masterはすべての音に適用します。ゲーム音声をUnityの既定出力から重ねて再生しないため、既定出力がP1機器であってもP2の曲や操作音は混ざりません。

既定の音量比は Master 100%、BGM 80%、エンジン 42%、効果音 100%です。成功・警告などの通知中はBGMとエンジンを約0.55秒だけ下げます。同じ確認／準備音や成功音は短時間に繰り返さず、出力には軽いソフトリミッターを通します。

ゴール後は走行音のDSPを維持し、ウイニングラン終了時にエンジンゲインを0へ落とします。結果BGMへ切り替える際は同じプレイヤーミキサーの出力を約0.35秒フェードアウトして曲を交換し、約0.55秒でフェードインします。効果音用ストリームやBGM用の重複ストリームは追加しません。リードは実機でゴール音・エンジン音・結果BGMの重なりを確認してください。

F8運営パネルには Quiet／Standard／Noisy venue の会場プリセットがあります。Noisy venue はMasterを最大、BGMを48%、エンジンを34%、効果音を最大にします。選択は次回起動後も保持します。定位診断を有効にすると、車両音ごとに出力先視点からの距離・左右パン・距離減衰を2秒ごとにログへ記録します。最終的なスピーカー配置での聞こえ方は実機で確認してください。

## 操作・レース進行の効果音

`Assets/Resources/Audio/SFX` に配置した19種類のオリジナルWAVを再生します。48kHz／16bit／ステレオの音源に、打撃・金属音・低音・空気音・和音・短い残響を事前に重ねています。ゲーム起動時のSE合成は行いません。エンジン音は従来の回転数連動方式を維持します。

- ボタンの選択と押下、長押し完了の決定。短押し・途中キャンセル・無効ボタンでは決定音を出しません。
- キーボード・ペダル・画面ボタンの準備完了とリザルト操作。
- 練習の課題達成、3・2・1の各数字、GO、本人のゴール、両画面のリザルト表示。
- ドリフト開始のタイヤ音、チャージ段階到達、ドリフト解放、加速パッド・ロケット・スリップストリームの発動、着地成功、クリスタル・ラインのチャージ取得、アイテム取得、シールド展開、車・壁への衝突、最終周突入。走行SEは人間プレイヤー本人へ送ります。
- 共有イベントは各出力へ一度ずつ送り、本人の操作・ゴールは本人の出力だけへ送ります。

`RaceSoundBank` がメインスレッドでWAVを一度だけ読み込み、ステレオPCMを共有します。`RaceSoundEffectsMixer` が各プレイヤーのBGM音声へ効果音を重ね、既存の `PlayerAudioCapture` がその後で独立機器へ送ります。音源と出力のサンプルレートが異なる場合は補間し、モノラル出力には左右平均を送ります。BGMと効果音のゲインをこのフィルター内で別々に適用するため、効果音専用のネイティブストリームは追加しません。CPU対応後はBGMと4台のエンジン音で5ストリームです。音声スレッドではメモリ確保・ロック・UnityオブジェクトやPlayerPrefsへのアクセスを行いません。同時再生は8音、衝突・加速・チャージには短い再生間隔を設け、重なった音のピークはソフトリミッターで抑えます。

音源の内容・差し替え方法・制作手順・試聴順は [SoundEffects.md](SoundEffects.md) を参照してください。`Artifacts/SoundEffects/preview.wav` で全音源を試聴できます。

`Racing > Validation > Sound Effects` または `-batchmode -executeMethod SoundEffectsValidation.Run -quit` で実音源のインポート設定・PCM、ステレオ、サンプルレート変換、同時再生のピーク、出力先、連打の重複抑止、独立ミュート、既存の音声出力とUIを検証します。音声部分だけなら `SoundEffectsValidation.RunAudioCore` を使えます。試聴用ステレオWAVを `Logs/SoundEffects` に保存します。`Play Race Flow` は実際のボタン・ペダル・レース進行から効果音が一度ずつ発生することも検証します。

## ネイティブプラグイン

macOS (Intel/Apple Silicon) とWindows x64用のプラグインを `Assets/Plugins/RaceAudio` に含めます。macOSはCore Audio、WindowsはWASAPIを使用します。音声のデコードはUnity、機器の列挙・独立出力はminiaudio 0.11.23です。固定版のソースとライセンスは `Native~/RaceAudio` にあります。Unityの音声スレッドから各機器のリングバッファへPCMを送信し、機器側でBGMと4台のエンジン音を混合します。機器のネイティブサンプルレートへの変換はminiaudioが行います。

### USB/HDMI機器での音切れ対策

各ストリームは、Playerでは50ms、Unity Editorでは120ms、またはUnity DSPブロック3個分の長い方を蓄えてから再生します（上限16384フレーム）。リング容量は32768フレームです。出力機器とUnityのクロック差は、キュー残量を平滑化して±0.5%以内の微小なリサンプルで補正します。デバイス側にも10ms×3期間を要求しますが、実際の期間はバックエンド／機器によります。通常の1024フレーム／48kHzでは、初期待ちバッファはPlayerで約64ms、Editorで120msです。

バッファ切れ時は短くフェードアウトし、必要量が再び貯まってからフェードインします。さらに、再充填の目標を40msずつ増やし、同じ遅延で音切れを繰り返すことを防ぎます（適応分は200ms、かつリング半分まで）。通常の送信で学習済みの目標を小さく上書きしません。機器の再オープン時に初期値へ戻ります。DSPのサンプルレートが変わっていない既定機器変更通知では、独立出力機器を開き直しません。実際の切断は従来通り検出し、再接続後はメニューから再検出します。

既存の橘諸兄はチュートリアル用として起動時の展開設定を維持します。約70秒のステレオ曲の展開後PCMには約25MB使います。新しいopening曲は約434秒、finish曲は約261秒あるため、レース用の2曲とともにストリーミング再生します。opening曲だけで約153MBになる展開後PCMを起動時に確保しない設定です。サンプルレート・チャンネル・圧縮品質は変更しません。

音切れが起きた場合は、メインスレッドのConsoleに出力先・累計回数・DSPサンプルレートを最大1秒に1回記録します。音声コールバック内でログを出しません。古いプラグインがメモリに残っている場合も再起動を案内します。**更新後はUnity Editorを一度終了して起動し直してください**。Play Modeの再開やスクリプトのリロードだけでは、ロード済みネイティブライブラリは更新されません。

オフラインテストは、2つの出力クロックを±1500ppmずらし、Unityの1024フレーム転送に−4〜+6msの揺れを加え、機器コールバックを480／960フレームとして10分間分を模擬します。バッファ切れゼロ、波形の連続性、ステレオ分離、容量上限、音切れ後の再開を検証します。実際のUSB機器での聴取確認は別途必要です。

追加のEditor向け検証は44.1／48／96kHzの各レートで60秒、2系統のクロック差と繰り返す80msの配送遅延・追いつきバーストを模擬し、音切れゼロと再生速度を確認します。修正前は最初の80ms遅延で音切れを再現しました。`Racing > Validation > Audio Buffering` は長尺4曲のストリーミング設定・チュートリアル曲の展開設定とPCM・ネイティブ追加APIを、スピーカーを開かず検証します。

今回の同梱バイナリ更新はmacOS（arm64/x86_64）です。Windowsでこの対策を使う場合は、下記手順でDLLも再ビルドしてください。

再ビルド:

- macOS: `sh Native~/RaceAudio/build-macos.sh`
- Windows: Visual Studioの「x64 Native Tools Command Prompt」で `Native~\RaceAudio\build-windows.cmd` を実行します（C++デスクトップ開発ワークロードが必要）。
- オフライン音声ミキサーテスト: `clang++ -std=c++17 -O2 Native~/RaceAudio/test-mixer.cpp -framework CoreFoundation -framework CoreAudio -framework AudioToolbox -lpthread -o /tmp/race-audio-test && /tmp/race-audio-test`
- Unity動作検証: `Racing > Validate Player Audio` または `-batchmode -executeMethod PlayerAudioValidation.Run -quit`。

実機ではP1だけ最終周に進めたときにP2の曲が変わらないこと、P2の最終周、ゴール直後から観戦・リザルトまでfinish曲が続くこと、各自のタイトル復帰、リトライで通常曲へ戻ること、機器の切断・再検出、音量変更と両機器の左右定位を確認してください。
