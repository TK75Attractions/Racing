# ESP32 シリアルコントローラープロトコル

Unity 側は 115200 bps、改行 `\n` で1台のマイコンから Player 1 / Player 2 の入力を読み取ります。

## USBポートの自動検出

UnityはUSBシリアルのポートを1つ選んで開きます。この環境のESP32はCP2102を使用しているため、`SLAB_USBtoUART` ポートを優先します。起動時の入力行はポート検出条件に使いません。`DEVICE` 応答や `IDENTIFY` コマンドは不要です。

自動検出できない場合は、`InputManager > ESP32 USB Serial > Port Name` にUSBシリアルのポート名を明示してください。2人分の入力は同じポートから受信します。

USBポートを開くとESP32が再起動し、起動ログやIMUキャリブレーションの行が先に届くことがあります。4列入力が始まるまでシリアルモニターには `INVALID` と表示され、P1/P2は待機状態になります。

## 入力フレーム

現在の2人用形式は次の4列です。

```text
<P1のペダル>,<P1のハンドル>,<P2のペダル>,<P2のハンドル>
```

例:

```text
0.75,-30,0.50,15
```

P1またはP2のペダル／ハンドルのどちらか一方でも `nan` の場合、そのフレームでは該当プレイヤーの入力全体を無視し、直前の有効な入力を保持します。もう一方のプレイヤーが有効なら、そのプレイヤーだけ更新します。

```text
nan,nan,0.50,15
```

上の例ではP1を無視し、P2だけを更新します。

### 旧形式（互換パーサー）

既存の2列形式も互換パーサーには残しています。ただし、1台のマイコンで2人分を送る場合は必ず上記の4列形式を使用してください。

```text
pedal,handle
```

- `pedal`: `-1.0` から `1.0`。正がアクセル、負がブレーキ／後退です。
- `handle`: 既存互換の生値です。Unity 側の `Steering Divisor`（初期値15）で除算されます。

旧2列入力にリセットと Ready をESP32から送る場合は、3列目と4列目を追加できます（互換パーサーのみ）。

```text
pedal,handle,reset,ready
```

- `reset`, `ready`: `1` / `0`、`true` / `false`、`on` / `off` を使用できます。
- 押下イベントを正しく検出するため、ボタンを離したフレームも `0` で送信してください。

既存互換の `||` 以降のデータは無視されます。

```text
0.75,-30,0,1||optional-data
```

入力は30 Hz以上で継続送信してください。初期設定では、有効な入力フレームを2秒間受信できなかったコントローラーを切断状態として扱い、車両入力をニュートラルに戻します。

## P1シリアル / P2キーボード デバッグ

`InputManager > Is P1 Serial P2 Keyboard Debug Mode` を有効にすると、P1はUSBシリアル、P2はキーボード入力になります。このモードは `Is Debug Mode` より優先されます。

- P1シリアル: 2列形式または4列形式の先頭2列
- P2アクセル／ブレーキ: 上／下矢印
- P2ハンドル: 左／右矢印
- P2リセット: Right Ctrl
- P2 Ready: Right Shift

4列形式を送信した場合も、P2のシリアル列は車両入力には使用されません。
