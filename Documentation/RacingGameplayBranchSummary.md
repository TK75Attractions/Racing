# このブランチの変更と今後の改善

更新日：2026-10-20（JST）。対象：`codex/racing-gameplay-features`、実装・検証の集約点：`8a43d23`。

1〜8節は`8a43d23`時点の集約。以降のチュートリアル修正・ウイニングランと見た目等の改善候補は9節へ追記した。

## 1. 対象範囲と現在地

ブランチは`ca2e842`から作成され、この文書追加前までに20件のcommitを積んでいる。ブランチ作成時点との差分は175ファイル。ゲーム機能・入力修正・検証プログラム・証跡・フォント更新・説明書を含む。

当初の機能候補A〜Gは実装済み。追加要望の強いハンドルアシスト、P2テスト自動運転、CPU攻防、高速旋回、AI高速化、ペダル関連の2件の修正も実装済み。専用タイムアタックとゴーストは未実装。自動検証を通過したことと、人が実機で遊んで採用判断できたことは区別する。

最初の[10作品比較・機能拡張計画](RacingFeatureResearchPlan.md)は`db210bd`で作成され、ブランチ作成前から存在した。このブランチではその計画を実装し、進捗を追記した。比較対象はマリオカート8 デラックス／ワールド、CTR、Sonic Racing: CrossWorlds、F-ZERO 99、Trackmania、GT7、Burnout Paradise、Split/Second、NFS Unbound。追加ボタンを増やさず、追走・ドリフト・着地・ライン選択を現在のハンドルとペダルで楽しめる方針を採った。

2人＋CPU2台、車種・塗装、通常のドリフト、アイテム、チューブ・壁面走行、復帰、基本HUD、監視・ダッシュボードは開始時点で存在した。監視のWebhook／自動起動、壁面からの復帰、MacBook筐体取付案もこのブランチ固有の追加には含めない。

## 2. 実装したゲーム機能

| 機能 | 現在の動作・変更内容 |
|---|---|
| A：体験／標準プリセット | Standardは通常2周・最大360秒、Experienceは1周・最大180秒。先着後の猶予上限も分ける。最初の車選択でルールを固定し、HUD・カウントダウン・終了条件へ反映。準備・走行中の変更は次レースへ予約する |
| B：ドリフト案内 | 安全な通常路面で「曲がってためる」「少し逆に切って加速」を短く表示。実際の解放成功に音と通知。ジャンプ・復帰・切断案内を優先する |
| C：連続妨害の抑制 | オイル・反転・スピンを重ねず、1回最大3秒、終了後1秒の保護。ジャンプ直前・空中の新規妨害を防ぐ。既存の復帰保護等と併用する |
| C：体験向けアイテム | Gentle itemsをONにすると1位はシールド、それ以外はロケット。切替時に残存する有害効果・オイルを除去。CPUのアイテム使用は追加していない |
| D：スリップストリーム | 人間の車が前車の後方6〜20m、横ずれ2.5m以内を約0.9秒追うと0.7秒の小加速。追走相手は人間・CPU。立体交差・壁越し・逆走・空中・ジャンプ付近では誤成立させない |
| 追加報酬の加速管理 | 追走・着地の追加加速は強い方だけ。既存の加速と合計18m/s²を超える分を足さず、追加報酬で32m/s以上へ加速しない。既存ブースト終了フレームの未反映分も考慮。既存ブースト自体をこの上限へ制限する仕様ではない |
| M相当：強い逸脱防止アシスト | 約0.55秒先の逸脱を予測。明確に外へ向かう入力は道路へ向きを戻す操舵に置換し、単に弱く足す方式から強化した。最大90度/秒の切替と約0.35秒の復帰保持。実際の切れ角上限内で動き、生のドリフト入力は維持する。通常路面向けで、チューブ壁面・空中・ジャンプ付近等では介入しない |
| E：着地成功と小報酬 | 指定ジャンプの正常な踏切→0.1秒以上の空中移動→2輪以上の安定接地0.08秒で成功。通常段差や復帰を成功扱いにしない。安全条件が揃えば0.5秒の小加速。前輪から接地した場合は最大0.9秒待つよう緩和。成功通知と加速を別々に切替できる |
| F：チューブ内チャージライン | 実チューブ下部の18m区間に緑の2本の選択ラインと方向表示。接地した正方向の連続通過で最大ドリフトチャージの25%を獲得。中央の通常ルートも走れる。同一プレイヤー・同一周回での反復獲得を防ぐ |
| G：結果の達成表示 | 保存した実績から、ドリフト・追走・着地・チューブ等の成功をプレイヤー別に1件表示。成功なしは周回・進捗を表示し、DNFを完走扱いしない。自動運転使用はテストの記録と明記する |
| P2テスト自動運転 | F8からP2を自動入力へ切替。タイトル／結果から「P1手動・P2 AUTO」のテスト開始も可能。車体と道路を観測して約0.06秒ごとに操舵・ペダルを決める。通常のポーズ・復帰・入力ゲートを経由し、手動へ戻す時はペダル解放を待つ |
| CPUの攻防 | 追いつく前の不要な減速を減らし、10秒の攻撃／6秒の抜き返し余地を設けた。空いた側を選ぶ追越、逆方向コースの左右座標・初期レーン、接触後の譲り時間3秒→0.65秒を修正。人間の勝利は固定せず、CPUも通常の走行で順位を得る |
| 自動運転・CPUの踏切と接触 | 踏切90m前から車間を調整。並走中の踏切・空中・着地直後に中央へ合流せず、横位置を保つ。車両抵抗に必要なペダルを算出し、踏み込み不足による失速を修正 |
| 高速旋回＋操舵減速 | 高速でも操舵倍率を0.65以上残し、通常操舵・ドリフト保護の横加速度目安を最大48m/s²へ拡張。深く切ると最大14m/s²の追加減速と持続ブースト抑制が働く。ブースト中のチューブカーブでも曲がりやすくする |
| 高速AIペース | P2自動運転・CPU・既定の走行ボットの巡航目標を50m/s（180km/h）へ。100m先まで5m刻みで曲率・制動距離を読み、カーブやジャンプへ事前減速。踏切目安32m/s。遠い低速プレイヤーにCPU全体の速度を合わせ続けず、近くの高速相手とは攻防する |
| HUD・日本語 | 追加機能の成功・AUTO・操舵減速を表示。通知の優先順位と静的日本語フォントを調整し、342文字の収録、結果画面の720p／1080p表示を検証 |

着地・チューブの周回内使用済み状態はOFFや復帰で消さず、切替による報酬の取り直しを防ぐ。追加加速や蓄積の中断・リトライ処理も各機能へ接続した。

仕様と操作の詳細は[GameplayFeatures](GameplayFeatures.md)、操舵は[Steering](Steering.md)、CPUは[NpcRace](NpcRace.md)を参照。

## 4. ペダル・通信の修正

### 踏み込むと「ペダルを離して再開」が頻発する

正常なTELが受信キューに届いていても、描画が止まった直後の物理更新が未反映の受信時刻を見て切断と誤判定していた。100msを超える停止で入力ゲートが解除待ちを保持し、以後は踏み込んだまま再開できなかった。

接続・鮮度を調べる前に受信済みキューをメインスレッドで反映するよう修正。受信時刻を保持するため、古いキューで本当の切断を隠さない。実PTYで修正前の150ms停止時に正常15フレーム・解析エラー0でも解除待ちになることを再現。修正後は150／350／650msの正常受信中の停止で入力を維持し、本当の通信停止・復帰時の解放ゲートも維持した。[原因と証跡](../Artifacts/PedalReleaseFix/README.md)

### タイトル表示後もしばらくペダルが使えない

機器の正常・校正済み状態を受け取っても、PINGや設定照会を含む全コマンドの応答待ちが角度準備を止めていた。準備条件をセッション確立・センサー正常・機器状態へ限定し、不要な応答待ちを分離。準備中の状態照会を2秒間隔から250ms間隔へ短縮した。

通信開始から最初の有効入力までを`First usable input`と`INPUT_READY`で計測できるようにした。READYと新しい有効TELは引き続き必須。遅延応答を使った回帰試験でソフト側の待ちを除去したことは確認済みだが、実ESP32の起動所要時間は未計測で、機器自身に必要な校正時間は省略していない。[修正と証跡](../Artifacts/InputStartup/README.md)

## 5. 走行・検証結果

### 2周2分の目標

現コースは1周1904.19m、2周3808.39m。2分には平均114.25km/hが必要。従来のP2自動運転24m/s（86.4km/h）、CPU25〜30m/sと一律カーブ減速が速度不足の要因だった。

| 計測条件 | 周回 | P1 | P2 | CPU1 | CPU2 |
|---|---:|---:|---:|---:|---:|
| 初期操舵調整・旧1829mコース | 2 | 3:09.36 | 3:01.86 | DNF | DNF |
| 攻防調整・中級同士 | 2 | 3:42.37 | 3:34.05 | 3:41.77 | 3:34.05 |
| 攻防調整・中級／上級 | 2 | 3:44.58 | 2:51.55 | 3:44.58 | 2:51.55 |
| 強アシスト負荷試験・P2 AUTO | 1 | 1:56.16 | 1:33.09 | 1:54.33 | 1:33.09 |
| 高速旋回調整後・中級／上級 | 1 | 1:52.10 | 1:29.61 | 1:50.60 | 1:29.61 |
| 最新6201・P1高速ボット／P2本番AUTO | 2 | **1:45.70** | **1:33.70** | **1:44.20** | **1:38.20** |
| 最新6202・P1／P2高速ボット | 2 | **1:46.99** | **1:36.49** | **1:43.99** | **1:39.49** |

最新2条件は本番SampleScene、通常2周、アイテムなし。全車が2分以内に完走し、コース逸脱0秒、復帰0回、最大停止時間0秒。1回目の平均速度はP1約131、P2約147、CPU約133／141km/h。異なる車・入力方針・アイテム・周回・コースの過去値から、一律の改善率は算出しない。全180台分の過去記録と出典を[CSV](../Artifacts/FastRacePace/historical-times.csv)へ集約した。[最新の条件・結果](../Artifacts/FastRacePace/README.md)

走行ボットは車の位置・向き・速度・角速度・接地・道路を観測してハンドルとペダルを入力する。通常レース中の位置・速度・周回・結果は直接設定しない。3倍速試走でも物理刻みは20ms、記録はGOからの公式ゲーム内タイムを使う。物理の単独比較試験では初期速度・配置を設定してから通常入力で走らせており、通常レースとは試験目的を分けている。

### まだ確認できていないこと

- 実ハンドル／ペダルでの補正の感触、高速旋回の扱いやすさ、起動後の入力可能時間。
- 初見者の完走率、ドリフトや報酬の理解度、CPUに対する公平感・再挑戦意欲。
- 最新の高速AIと低速プレイヤー、妨害あり、混雑・接触・連続レースを組み合わせた十分な反復計測。
- 本番の2実モニター・2音声出力・実USB機器での入力遅延、60fps目標、長時間運営。

保存された`runtimeErrors=[]`は走行記録区間の値。Unity起動時の既知のSearch索引処理等までエラーなしという意味ではない。2周2分も最新2条件の実績であり、事故・低速運転・妨害がある全レースに保証するものではない。

## 6. これから行う改善の順番

以下は既存計画の残作業と、直近の修正を踏まえた推奨順。未実装を実装済みと混同せず、各項目で比較条件・完了条件を決め、小さくcommit／pushする。新しい独立機能はF8の個別切替へ追加する。

| 順 | 改善 | 作業と完了条件 |
|---|---|---|
| 1 | 実入力の起動・再開を確定 | コールド起動／再起動／USB再接続で`INPUT_READY`と機器状態を記録。タイトル表示→操作可能までを分離計測し、残る遅延を特定。踏み込み継続中の誤解放待ちがなく、本当の切断後は安全に解放を待つことを実機で確認 |
| 2 | 高速化後の攻防と運転感を再調整 | 低速・中速・高速の人間役、P2 AUTO、アイテムON/OFF、複数乱数で試走。タイムだけでなく近接時間・相互追越・接触・停止・復帰を記録。遅い人を置き去りにし続ける、抜いた直後に不自然に待つ、ジャンプで押す等を直す。2分を狙う条件と初見者の遊びやすさを分けて評価 |
| 3 | 人の実機試走と本番構成確認 | 初見者8〜12人程度＋経験者で探索的評価。初回完走、ドリフト理解、補正への違和感、着地・ラインの理由の理解、CPUの公平感を記録。2画面・2音声・実入力でフレーム時間、入力遅延、連続した次組切替も確認し、強すぎる支援や見づらい通知を修正 |
| 4 | I前提：競技用の記録検証 | 正方向の区間順序・走行進捗・復帰履歴・運営終了・設定変更を記録。ゴール往復や区間省略で有効記録ができないことを確認。体験モードの既存進行と分離する |
| 5 | I：1人用タイムアタック | 固定車・固定ルール・1周、CPU／ランダムアイテムなし、ローカル保存から開始。相手の準備を待たず開始・終了・再挑戦可能にする。人の試走で目標タイムを決める。コース版・物理版・ルール・支援設定を保存し、AUTO／無効走行を競技記録へ混ぜない |
| 6 | J：自己ベストゴースト | Iの後、位置・回転・必要な見た目を約20Hzで記録し補間再生。衝突・取得・順位へ影響させず、コース版違いを拒否。参加者を識別できる保存方法にし、P1/P2スロットの記録を個人の自己ベストと呼ばない |
| 7 | H：ペダルのスタート加速を試作 | 起動・解放ゲートが安定してから、GO付近の踏み込みで小報酬を検討。通常スタートを妨げず、入力遅延差や誤発進、序盤格差が増えない場合に採用 |
| 8 | K：最終周の演出変化 | 照明・看板等の軽い変化を試し、路面・進路・HUDの視認性と2画面負荷を保つ。既存の最終周BGMと合わせて評価 |
| 9 | L：距離差によるアイテム抽選 | 高速AIと追走のバランスが固まってから、順位に加えて実距離差を使う試作。連続妨害や過剰な逆転を増やさず、接戦の体験が改善した場合に採用 |

1〜3は未確認事項を潰すための現時点の推奨。4〜6が当初ロードマップの次段階「反復プレイ」。7〜9は当初からの追加候補で、採用を確約した機能ではない。日付指定の納期は未設定。会場の対象者・希望回転時間・本番機器が確定したら評価基準を調整する。

手動アイテム保持・発射、自由ジャンプ・グライダー、常時破壊される道路、大量の妨害、天候グリップ、多数CPUも当面採用しない。現状の操作機器・立体コース・会場運営への影響が大きいため、必要性が明確になってから再評価する。
