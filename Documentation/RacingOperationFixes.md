# 操作・周回・スタート演出の修正

## 動作

- 管理画面のプレビューは、プレイヤーのカメラスタック全体を同じ640×360ターゲットで描画し、描画後に元のターゲットとCanvas倍率を復元する。追加ディスプレイへの映像出力はプレビュー取得中に行わない。ブラウザーは取得の重複と5秒を超える取得待ちを防ぎ、JPEGの復号後に表示を切り替える。一時的な取得失敗では直前の正常画像を保持し、Unity切断時に消す。
- 接続初期化後に両センサーが正常な未校正装置へCALIBRATE ALLを自動送信する。校正済みで角度基準だけがない場合はANGLE_ZEROを送る。校正済みREADYには送らず、手動操作と重複させない。入力はREADYと新しいTELを待つ。失敗した校正を新しい要求番号で繰り返さない。
- ハンドルで選択したボタンを明るい背景、濃い文字、太い枠、側面のマーカーと拡大で強調する。別ボタンにマウスが残っていてもハンドルによる選択を優先する。
- 前方の路面と2輪以上の支持を確認し、18cm以下の路面の継ぎ目・段差を予測して乗り越えを補助する。連続する近い路面から離れる方向の速度だけを抑え、道路方向の速度を残す。路面が途切れるジャンプや、路面から離れた飛行には適用しない。
- 周回加算からチェックポイント条件を撤廃する。ゴール通過ごとに加算し、複数Colliderによる二重加算を防ぐ。旧チェックポイントのTransformはスタート位置の参照として残す。ゴールの先端接触時も順位用の距離を連続させる。
- 完走・棄権した車のエンジンは停止し、全体のゴール演出・結果画面・タイトルでは全エンジンを無音にする。合成音とプレイヤー別出力の両方で制御する。
- SampleSceneのゴールには道路幅に合わせたCircuitFinishGateを配置する。既存のNeonGoalGateの両面FINISHサインを使用し、装飾用Colliderは追加しない。配置のやり直しはRacing > Place Finish Gate at Goalで行える。
- 3→2→1に合わせて赤いライトが左から1つずつ増え、GOで3つとも緑になる。再挑戦時には点灯状態を初期化する。

## 検証

```sh
./Tools/Validate-Rgp.sh
node --test Tests~/Dashboard/dashboard-ui.test.cjs
```

Unity 6000.3.9f1で、次を隔離したバッチエディターで実行する。

```sh
Unity -batchmode -projectPath <project> -executeMethod RoadSeamValidation.RunAllFixes -quit -logFile <log>
Unity -batchmode -projectPath <project> -executeMethod RacingFixPreview.Run -quit -logFile <log>
```

前者は本番車両による3・8・15cmの段差×15・30・45m/sの9条件、ジャンプ端・空中、ゴール加算・二重接触・再挑戦、順位境界、UI選択とライト、音声出力、異なる画面サイズのプレビューと復元、ゴールゲート配置を検査する。後者は結果の左右選択と3・2・1・GOを `/private/tmp/racing-fix-previews/` に画像出力する。実ESP32のセンサー校正と、実際の外部モニター・音声機器の組み合わせは別途実機で確認する。
