# 管理画面を他の人に見てもらう手順（主催者向け）

対象：ゲーム用Macを管理し、参加者を招待する人。参加者には別紙の[参加者向けマニュアル](DashboardSharingParticipant.md)を渡してください。

この手順では、参加者が各自のTailscaleアカウントを作り、主催者がゲーム用Macを「端末共有」します。参加者は自分のネットワーク（tailnet）のまま接続できます。主催者のアカウントを教えたり、参加者全員を主催者のtailnetへ追加したりする必要はありません。[端末共有とユーザー招待の違い（公式）](https://tailscale.com/docs/reference/inviting-vs-sharing)

## 1. 最初に準備するもの

| 項目 | 用意するもの |
| --- | --- |
| ゲーム用Mac | インターネット接続、UnityのRacingプロジェクト |
| 主催者のアカウント | 自分のGoogleなど、Tailscaleのログイン画面で選べるアカウント |
| 参加者の端末 | スマホ・タブレット・PCのいずれかと、各自のTailscaleアカウント |
| 配布する情報 | 参加者ごとの共有招待リンク、管理画面URL、閲覧する日時、連絡先 |

すでにMacでTailscaleを使っている場合は、そのアカウントと設定を使い、手順2の未完了部分から進めます。

## 2. 自分のアカウントを作り、Macを接続する（初回のみ）

1. ゲーム用Macで[Tailscale公式サイト](https://tailscale.com/)を開き、**Get Started**から登録します。
2. ログイン画面でGoogleなどの認証方法を選び、自分のアカウントでログインします。利用目的などを聞かれたら実際の用途に合わせて入力します。
3. [公式ダウンロードページ](https://tailscale.com/download)からMac用Tailscaleをインストールします。初期案内に従ってVPN構成などの必要な許可を承認します。
4. Tailscaleアプリでも、手順2と同じ認証方法・同じアカウントでログインします。接続をオンにして、**Connected／接続済み**になったことを確認します。
5. [Tailscale管理コンソールのMachines](https://login.tailscale.com/admin/machines)を開き、ゲーム用Macが表示されることを確認します。Macの端末名とTailscaleのIPアドレスを控えます。

登録から端末追加までの案内は[公式クイックスタート](https://tailscale.com/docs/how-to/quickstart)も参照できます。料金・利用条件は登録画面で確認してください。

## 3. 管理画面を起動し、参加者用URLを取得する

1. 初回はMacに[.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)もインストールします。
2. Tailscaleを接続した状態でUnityのRacingプロジェクトを開き、**Racing > Start Dashboard and Play**を選びます。
3. 初回のHTTPS設定を求められたら、**Racing > Dashboard > Tailscaleの初回HTTPS設定を開く**、または起動時に表示されたTailscaleの設定リンクから有効化し、もう一度ダッシュボードを起動します。
4. Macのブラウザーで管理画面が開き、**UNITY 接続中**と表示され、状態が更新されることを確認します。直接開く場合は `http://127.0.0.1:8766/` です。
5. **Racing > Dashboard > 別端末用URLをコピー**を押して、参加者用URLを控えます。形式は `https://<PC名>.<tailnet名>.ts.net/` です。山括弧部分を含むこの例を配らず、コピーした実際のURLを配ってください。

参加者が使うのは、このHTTPSのURLです。`127.0.0.1`はその端末自身を指すため、MacのローカルURLを参加者へ送っても接続できません。GitHub Pagesの画面は別方式なので、今回のURLと取り違えないでください。

このプロジェクトはTailscale Serveを使います。通常はUnityの起動処理が設定するため、Serveのコマンド入力は不要です。Funnelによる一般公開や、ルーターのポート開放も不要です。[Serveの仕組み（公式）](https://tailscale.com/docs/features/tailscale-serve)

## 4. 招待した人も操作できるようにする

### 管理画面の操作権限

**「操作担当者（任意）」に `*` を設定すると、招待した人もレース進行・装置操作を行えます。** TailscaleでこのMacへの接続を許可され、本人確認できた利用者全員が対象です。参加者のログイン名を1人ずつ追加する必要はありません。

Unityが起動した中継を使う場合は、**Racing > Dashboard**の「操作担当者（任意）」へ `*` を入力し、**停止**してから「ダッシュボードを開く」で起動し直します。

Macの常駐中継を使っている場合は、Unityの欄を変えても既存の中継が再利用されます。この場合はプロジェクトのルートで次のコマンドを実行し、常駐アプリと操作権限を更新します。

```sh
RACING_DASHBOARD_OPERATORS='*' sh 'Tools/DashboardRelay/Install Dashboard Service.command'
```

個別に操作担当を絞りたい場合は、`*` の代わりに主催者と担当者のTailscaleログイン名をカンマ区切りで指定します。Unityの欄が空欄の場合は、ゲーム用MacのTailscaleユーザーのみが操作担当になります。参加者は各自のアカウントを使って接続します。

### Macへの接続範囲

端末共有の対象はMacです。管理画面だけに接続を絞るには、[管理コンソール](https://login.tailscale.com/admin)の**Access controls**で、共有ユーザーからゲーム用Macへの通信を**TCP 443のみ**に制限します。他のサービスも同じHTTPS入口で配信している場合、そのサービスも到達可能になるので確認します。

設定例は次のとおりです。`100.101.102.103`は例なので、Machinesに表示されたゲーム用Macの実際のTailscale IPv4アドレスに置き換えます。

```json
{
  "grants": [
    {
      "src": ["autogroup:member"],
      "dst": ["*"],
      "ip": ["*"]
    },
    {
      "src": ["autogroup:shared"],
      "dst": ["100.101.102.103"],
      "ip": ["tcp:443"]
    }
  ]
}
```

これは「自分のtailnetのメンバーは従来どおり接続でき、端末共有した外部ユーザーはゲーム用MacのHTTPSだけに接続できる」という、この運用向けの例です。既存のポリシーはコピーして保存してから編集し、他の用途の設定がある場合は必要なルールを残して統合します。既存の制限をこの例のメンバー向け全許可で広げないでください。

**すべてを許可する既存ルールを残したまま、443のみのルールを追加しても制限にはなりません。** `acls`と`grants`の両方を確認し、外部共有ユーザーにも適用される `src: ["*"]` などの広い許可を整理します。編集画面の検証が成功してから保存し、主催者の接続が維持できることを確認します。[共有ユーザーの制御（公式）](https://tailscale.com/docs/features/sharing#sharing-and-access-control-policies)、[grantsの設定例（公式）](https://tailscale.com/docs/reference/examples/grants)

## 5. 参加者ごとに共有招待リンクを作る

1. 参加者に別紙を渡し、各自のアカウント作成とTailscaleアプリへのログインを済ませてもらいます。
2. 主催者は[Machines](https://login.tailscale.com/admin/machines)でゲーム用Macの **… > Share**を開きます。Usersのユーザー招待ではなく、Macの共有を使います。
3. **Copy invite link**タブを選び、**Reusable linkをオフ**にして、**Copy share link**で招待リンクを作ります。
4. 招待リンクと、手順3でコピーした管理画面URLを、対象の参加者へ個別に送ります。招待リンクは参加者ごとに作成します。
5. 参加者が承認したら、同じShare画面で相手のプロフィール・ログイン名を確認します。メールアドレスを宛先に招待する場合も、承認に使ったアカウントを確認してください。

招待リンクは未使用のまま30日経つと失効します。単回使用リンクを別の人が使用した場合や、失効した場合は再発行します。招待リンクは接続権限を受け取るためのものなので、公開の場所には載せません。主催者には端末共有を管理できる権限が必要です。[共有・招待・解除の操作（公式）](https://tailscale.com/docs/features/sharing)

### そのまま送れる案内文

以下の空欄を実際の値に置き換えて送ります。参加者向けマニュアルは、この文章と一緒に添付するか、相手が開ける場所に置いてください。

```text
レース管理画面の閲覧・操作の案内です。
添付の「参加者向けマニュアル」に沿って、各自のアカウントでTailscaleを準備してください。

閲覧日時：［日時・日本時間］
共有するPC名：［ゲーム用Macの端末名］
初回の共有招待リンク：［この人用の招待リンク］
管理画面URL：［コピーした https://～.ts.net/ のURL］
接続できないときの連絡先：［連絡先］

初回は招待リンクを承認し、閲覧する端末のTailscaleをオンにしてから管理画面URLを開いてください。
2回目以降はTailscaleをオンにして、管理画面URLを開くだけです。
招待した人もレース進行や装置操作ができます。操作すると実際のゲームに反映されるため、担当者同士で声をかけて操作してください。
招待リンクの転送は控えてください。
```

## 6. 当日の確認と終了後の解除

1. Macを起動・ログインしたままにし、インターネットとTailscaleを接続して、利用中はスリープさせません。
2. **Racing > Start Dashboard and Play**でゲームと管理画面を起動します。
3. まず参加者1人に、別回線の端末から接続してもらいます。画面に**Tailscale / WebSocket**と表示され、状態やシリアル情報が更新されること、現在の進行段階で使用できる操作ボタンが有効なことを確認します。初回の操作確認は、主催者と合図を合わせてテストレースで行います。
4. 確認後、他の参加者にも同じ手順で接続してもらいます。この実装の同時WebSocket接続は最大8です。主催者のタブも含むため、不要なタブを閉じます。
5. 閲覧権限を終了する場合は、Machinesのゲーム用Macの**Share**から対象者の **… > Revoke invite**で共有を取り消します。未使用の招待も同じ画面で取り消せます。再び許可する場合は新しい招待を作ります。

Unityだけが停止している場合、中継が動いていればページは開けますが、レース情報は更新されません。常駐中継の設定は[統合ダッシュボードの設定手順](RealtimeDashboard.md#macで常時開けるようにする)を参照してください。

## 接続できない場合

| 症状 | 主催者側で確認すること |
| --- | --- |
| 自分は開けるが参加者は開けない | 招待承認済みか、承認時とアプリが同じアカウントか、Access controlsで共有ユーザーのTCP 443が許可されているかを確認 |
| 管理画面が開かない／タイムアウト | Macの電源・スリープ・Tailscale接続、Mac内の `http://127.0.0.1:8766/` が開くかを確認 |
| URLを開くとファイル保存になる／502 | 中継が動いているかを確認。必要なら `Tools/DashboardRelay/Start Dashboard.command` を起動し、開いたターミナルを閉じない。参加者にはブラウザーでHTTPSのURLを開き直してもらう |
| ページは開くがUNITY未接続／再接続中 | UnityをPlayし、Mac内でも情報が更新されるか確認 |
| 403／アクセス拒否 | コピーしたHTTPS URLを使っているか、中継の接続先設定、Serve経由の本人情報を確認。タグ付きの参加者端末は本人情報が付かないため、ユーザーでログインした端末を使用 |
| 閲覧専用と表示される | 起動中の中継に操作担当者 `*` が反映されているか確認。常駐中継は上記コマンドで更新し、参加者にはページを再読み込みしてもらう |
| 接続が不安定／429 | 不要な管理画面タブを閉じ、同時接続数を減らす |

参加者への共有・閲覧の実機確認は、上記の当日確認で行ってください。このマニュアルはプロジェクトの実装とTailscale公式資料を照合して作成したもので、招待やアクセス設定を自動で変更するものではありません。
