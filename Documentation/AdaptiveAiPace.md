# 周囲に合わせるCPU・P2自動運転

CPUの高速走行能力を維持し、常に最高ペースで走る代わりに、実際の人間プレイヤーのペースと進捗差に合わせてペダルを操作する。

## 基準となるプレイヤー

`RaceHumanPace` が人間の車の前進速度を物理ステップで観測する。P2自動運転は難易度の基準に含めない。CPU 1／CPU 2の相手の選択は従来同様で、人間2人が80m以上離れた場合はそれぞれ後方／前方の人を相手にする。相手の完走やP2自動運転への切り替え時は、走行中の人間へ変更する。

基準ペースは初期18m/s。上昇3m/s²・下降1.5m/s²までで更新するため、一瞬のブーストや減速へ追従しすぎない。停止・空中・妨害・操作ゲート待ちなどは3秒間ペースを保持する。長く止まった場合は徐々に下がるが、CPUは最低8m/sを目標としてレースを続ける。基準となる人間が全員完走・離脱した場合は通常巡航へ戻る。

## CPUの攻防

CPU 1は相手に近い位置、CPU 2は少し前方を狙う。16秒周期の攻撃／抜き返しの余地を作る時間帯は低速プレイヤーにも適用し、先行しすぎた場合はその距離に応じて減速する。以前の高速ペースにあった「低速の相手なら50m/sへ戻る」「先行CPUの目標が最低28〜38m/sになる」条件を、標準ONの制御では使わない。

大きく遅れたCPUは最大52m/sの目標まで追走できる。巡航目標の変化は加速6m/s²・減速4m/s²までとし、実際の加減速は既存の車両物理と通常ペダル入力に任せる。順位や勝者は固定せず、ワープ・速度の直接代入は行わない。コーナー・前車・着地・接触後の安全制御を優先する。

## P2自動運転

人間P1の約10m後方を基準に走る。近くではP1のペースに合わせ、離されたときは追いつき、先行したときはペースを下げる。P1が速ければ最大50m/sの巡航能力を使える。ジャンプ手前では必要な進入速度24m/sを確保し、その後で前車との間隔確保を優先する。CPUもジャンプ前には同じ最低進入目標を使う。

## デバッグと比較

F8の `Adaptive CPU / P2 pace around manual players` は既定ON。OFFで以前の固定高速・高速CPUペースへ戻して比較できる。`Fast AI pace` は最高速度と先読み性能、`CPU overtaking / counterattack` は従来の攻防・レーン制御の切り替えとして残る。AdaptiveがONの間は、後者をOFFにしてもプレイヤーに合わせる速度制御は続く。

## 検証

`Tools/Validate-Rgp.sh` は低速／高速の追い抜きと抜き返し、先行時の抑制、遅れた場合の高速追走、P2の追従、停止・被弾時の観測保持、時間刻みへの独立性を検査する。

実コースでは、人間相当の反応間隔・ハンドル速度を持つ入力ボットで低速2人、速度差のある2人、高速2人、P1＋P2自動運転を試走する。既存の曲率・車体状態・交通を観測して操舵／ペダルだけを入力し、車両位置・速度や結果を強制しない。結果は [AdaptiveAiPace](../Artifacts/AdaptiveAiPace/README.md) を参照。
