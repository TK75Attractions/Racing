# Tsukukoma Circuit UIモーション

作業ブランチ: `codex/ui-motion`。元のデザイン2と画面端の通知構成を維持する。

## 共通ルール

- 操作反応はおよそ0.10〜0.18秒、要素の入場は0.24〜0.36秒、時間差は0.045秒前後。
- 三次のイージングと有限の減衰振動を共有。大きな移動は画面切替とゴールに限定し、走行中は数字・メーター・画面端だけを動かす。
- UI時間はunscaled。停止中も操作反応を保つ。実際の走行値・順位・タイムは変更しない。
- 繰り返しは現在の姿勢から再開し、取消・無効化で基準位置・大きさ・色を復元する。
- 配列や表示用部品は構築時に確保し、安定中はメッシュを更新しない。長押しの判定とゲージは入力の実時間に従う。

## 順位とメーター

順位の数字は上昇時に下から、下降時に上から入り、短い拡大と色変化で着地。順位表も行が滑らかに入れ替わる。安定した順位・名前・距離の再フォーマットを避ける。

速度の針は約65ms、回転数・ブーストは約45msの時定数で追従する。急減速はすぐに移動方向を反転する。針には小さな加減速の軌跡、ブースト発動には有限の外周反応を付ける。主数字は実測値を表示し、補間した架空のタイムを見せない。初期表示・観戦先の切替では古い車の値を引き継がない。

## 検証

`UIMotionValidation.RunFoundation` と `RunMeters` は製品用の部品を生成し、再実行・取消・順位方向・急減速・追従の収束・不正値を検査する。安定したメーターへ1000回同じ値を渡し、メッシュ再構築0回・managed allocation 0 bytesを検証する。

通常のEditModeではMonoBehaviourの無効化ライフサイクルは再現されないため、静的検証では公開取消APIを実行する。実際のOnDisableと画面の中断はPlay Modeで確認する。
