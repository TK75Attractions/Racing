# Tsukukoma Circuit UIモーション

作業ブランチ: `codex/ui-motion`。元のデザイン2と画面端の通知構成を維持する。

## 共通ルール

- 操作反応はおよそ0.10〜0.18秒、要素の入場は0.24〜0.36秒、時間差は0.045秒前後。
- 三次のイージングと有限の減衰振動を共有。大きな移動は画面切替とゴールに限定し、走行中は数字・メーター・画面端だけを動かす。
- UI時間はunscaled。停止中も操作反応を保つ。実際の走行値・順位・タイムは変更しない。
- 繰り返しは現在の姿勢から再開し、取消・無効化で基準位置・大きさ・色を復元する。
- 配列や表示用部品は構築時に確保し、安定中はメッシュを更新しない。長押しの判定とゲージは入力の実時間に従う。

## 順位とメーター

順位の数字は上昇時に下から、下降時に上から入る。約60msのつぶれから縦長の伸び・小さな反動・着地へつなぎ、色の反応と短い速度線を添える。順位は約0.48秒、周回・カウントダウン・リザルト等は約0.44秒で収束する。数字は実値のまま、アクセント線は既存の文字枠内に収める。順位表も行が滑らかに入れ替わる。安定した順位・名前・距離の再フォーマットを避ける。

速度の針は約65ms、回転数・ブーストは約45msの時定数で追従する。急減速はすぐに移動方向を反転する。針には小さな加減速の軌跡、ブースト発動には有限の外周反応を付ける。主数字は実測値を表示し、補間した架空のタイムを見せない。初期表示・観戦先の切替では古い車の値を引き継がない。

ハンドル表示と実際の入力・車両制御には補間遅延を追加しない。P1の青とP2のピンク、既存の文字サイズ・メーター形状を継承する。

## 画面と操作

| 対象 | 演出と目的 |
| --- | --- |
| 画面切替 | 5本の斜めシャッターが時間差で走る。閉じる約0.48秒、開く約0.56秒。プレイヤー色の縁と濃い帯で画面の所属を保つ。両端を滑らかにした対称のイージングを使い、帯の移動が画面内で見える時間を確保する。画面内容の切替は完全に覆った時点で行う。 |
| タイトル・HUD | ロゴ・案内、HUDのまとまりが短い移動と小さなスプリングで入場。背景や道路自体は動かさない。 |
| ボタン | 選択時の小さな浮き上がり、押込み、矢印の移動、光の走査、決定時の一回の反応を共通化。決定の約0.08秒後に処理する。車選択の矢印・カードは即時反応する。 |
| 長押し | 実際の入力時間とゲージを同期。途中解除で取消し、確定は一度だけ。画面を閉じた保留操作は次の画面へ持ち越さない。 |
| 車選択 | 車のプロフィールと性能値を時間差で表示し、性能バーは短く追従。車の台と既存の選択操作を維持。 |
| チュートリアル | 既存のレースHUDを使用。課題の切替時に説明を短く入場させ、達成時はステップだけを強調。 |
| コース・ESC・終了 | 案内と操作群を小さく時間差で入場。再表示で位置や拡大率が累積しない。 |
| 実況・観戦 | モードや観戦先のラベルに短い反応を追加。カメラ画像・リプレイ動画の領域を拡大移動させない。 |

## レースの節目

- 順位変動は数字の上下移動と拡大、上昇／下降の色を組み合わせる。順位表の行も新しい位置へ滑らかに移る。
- 周回更新は数字の反応と周回バーの短い入場。カウントダウンは既存の信号・数字を共通の値アニメーションで強調する。
- アイテム取得・使用、ブーストのトーストは画面端から18px入場する。拡大で道路側へせり出さず、既存の約1.6秒の寿命を維持する。
- 接近・ジャンプ・ドリフトなどは従来どおり端の静かな通知欄。内容が変化した同一通知を毎回フェードし直さない。効果の残秒は0.1秒単位で表示更新する。
- 残り10秒の警告は秒が切り替わった瞬間だけ反応。ゴールは見出し→順位→タイムの順に着地し、プレイヤー色の紙吹雪を添える。
- 現行ゲームの中間チェックポイント判定は無効化されているため、演出のために復活させない。実際に発火する周回・着地・チューブ等の既存通知を対象とする。

## リザルト

両ボタンは共通の白い基本形とし、選択中のみ濃い背景・明るい文字・三角ポインター・色付きのコーナー枠と下線を表示する。再戦とタイトル帰還で同じ強調を交換する。ポインターは実際のペダル選択を即座に示し、別ボタンをマウスでホバーしても選択中の表示が二重にならない。一般のボタンもフォーカス時のコーナー枠を共有する。以前は再装飾時に2枚の面が重なっていたため、アニメーションが所有する面だけを表示する。透明なクリック用Imageは有効のまま保つ。

見出し、本人の順位と実測タイム、順位表の各行、本日の順位を約0.54秒で段階表示する。タイムの架空のカウントアップはせず、DNFもそのまま表示する。操作群は約0.10秒から入場する。退出時も要素が短く移動し、共通シャッターへつなぐ。リプレイ領域は固定したままにする。

## 中断と負荷

`UIRevealSequence` と `UIValuePulse` は有限の状態更新を行い、再生ごとの配列やコルーチンを生成しない。数字の着地アクセントも構築時に一度だけ作り、再利用する。無効化・取消で基準姿勢へ戻す。画面切替には世代番号を設け、古い完了通知・覆いの解除・ゴールの観戦移行が新しい状態を上書きしない。覆いのコールバックから即時画面切替された場合も旧処理を止める。

UIの入場開始時刻は実時間から測り、画面生成の重い最初のフレームで演出が一瞬で終わることを避ける。走行中はメーターの数値・メッシュを量子化し、静止時の再構築を抑える。色の解析・車コンポーネントの検索はホットパスから外す。

## 検証

`UIMotionValidation.RunFoundation` と `RunMeters` は製品用の部品を生成し、再実行・取消・順位方向・急減速・追従の収束・不正値を検査する。安定したメーターへ1000回同じ値を渡し、メッシュ再構築0回・managed allocation 0 bytesを検証する。

通常のEditModeではMonoBehaviourの無効化ライフサイクルは再現されないため、静的検証では公開取消APIを実行する。実際のOnDisableと画面の中断はPlay Modeで確認する。

| 検証エントリ | 範囲 |
| --- | --- |
| `UIMotionPerformanceValidation.Run` | 順位の予備動作・縦伸び・アクセントの描画範囲と取消、繰返し時の割当、追従、選択、遷移の実メッシュ、周回／通知／ゴール、両配色のリザルト選択の排他性と文字コントラストを連続検査。ウォームアップ後の動く速度計メッシュを200回再構築しmanaged allocation 0 bytesを検査。 |
| `UIMotionPlayModeValidation.RunAll` | 実際のUpdate/OnDisable、timeScale=0、重複切替、完了一回、中断、コールバックからの再入、ゴール差替え、ボタン保留取消、通知の再フェード防止、リザルトの再表示。 |
| `CarSelectionPlayModeValidation.Run` | SampleSceneでP2先行の独立選択、長押し、チュートリアル、解除ゲート、両者のレース開始。 |
| `MultiplayerPlayModeValidation.RunBatch` | SampleSceneの加速・アイテム・ゴール・観戦・結果・再戦・終了／タイトル帰還などの既存フロー。結果ではハンドル相当のテスト入力を注入して左右を切替え、P1の操作でP2の選択が変わらないことも確認。 |
| `ArcadeUIValidation.RunRegressionChecks` | 既存レイアウト、通知欄、フォント、固定配色、ランキングなどの表示契約。 |
| Unity Test Runner / EditMode | 既存のゲームロジック等の回帰検証。 |

Unity 6000.3.9f1で実行する。`-executeMethod`型の静的検証には`-quit`を付け、Play Mode検証と`-runTests`には付けない（検証側が終了する）。同じプロジェクトのUnityを同時起動しない。

割当の検証値はウォームアップ後の対象部品・対象スレッドに限る。ゲーム全体のGCゼロや実機FPSを保証するものではない。実筐体のペダル・ディスプレイ環境での体感確認は別途必要。

プレビューと今回の実行結果は [Artifacts/UIMotion](../Artifacts/UIMotion/README.md) を参照。
