# ハンドル補正・下端インディケーターの検証

2026-10-17（日本時間）、Unity 6000.3.9f1。`4099e07` を基点にした作業ツリーで実行。

## 変更と測定

- 30 m/sを超えても速度の二乗に反比例して操舵倍率を下げ続ける。横加速度目安22 m/s²とホイールベースから、速度別の前輪角上限も計算する。
- 中央±0.08入力単位を不感帯にし、45msの時定数で平滑化。大きな中央復帰・切り返しは時定数を55%にする。上限外の入力は平滑化前に収め、切り返し時に過剰な入力履歴を残さない。
- 両者の画面下端に横線・入力位置・実操舵位置・有効範囲を表示。上限外の両端を暗くし、日本語で説明する。観戦対象にも追従する。既存の小型ハンドル表示も同じ入力範囲へ正規化した。

| 入力応答の測定 | 結果 |
| --- | ---: |
| 入力の90%に達する時間 | 120 ms |
| 左右反転後に中央を通過する時間 | 20 ms |
| 中央±0.07入力の模擬ノイズ | 操舵角0° |
| 16.7 Hzの模擬ノイズ、振幅±0.3入力単位 | 出力RMSが入力の25.0% |
| 切れ角上限の超過（全58試験） | 0° |

応答時間は50 Hzの合成入力で測定した車両側処理の値。実機IMUの校正、センサー内部の処理、シリアル・USB転送遅延は含まない。SampleSceneの除算値6.5では不感帯は実ハンドル約±0.52°、模擬ノイズ振幅は約±1.95°相当。

## Play Modeの物理試験

**58ケースすべて通過。** [結果](physics/result.txt)、[全測定値](physics/report.json)、[物理刻みの記録](physics/trace.csv)、[応答とソースのハッシュ](metrics.json)。

既存41ケースに、8/20/40/60 m/s × 左右 × 小入力/大入力の16ケースと中央ノイズ1ケースを追加した。既存の離陸・着地・裏返り・ドリフト・スピン保護・空中慣性の検査も通過。

| 試験開始速度 | 大入力ケースの最大ヨー角速度 | 最大横滑り角 |
| --- | ---: | ---: |
| 8 m/s | 1.749 rad/s | 8.72° |
| 20 m/s | 1.066 rad/s | 1.33° |
| 40 m/s | 0.618 rad/s | 0.37° |
| 60 m/s | 0.490 rad/s | 0.28° |

各ケースは加速しながら0.7秒旋回→0.3秒切り返し→0.8秒中央復帰する。一定速度の定常旋回ではない。追加16ケースの最終横滑り角は最大0.020°、車体傾斜は0°だった。

試験はSampleSceneと本番車両Prefabを使い、専用の平坦な路面で各条件を分離した。描画フレームの遅延で待機時間が伸びないよう固定物理時刻で待機し、物理試験中はカメラ描画を停止する。固定刻み0.02秒、時間倍率3。外部へのレース公開は無効。

## 表示と回帰検証

両者のHUD、入力と実操舵の区別、左右の制限、制限中の説明、変化のないフレームでメッシュを再生成しないことを検査した。720p/1080pの4枚で文字の欠落・切れを確認し、画像も目視確認した。

- [高速時 720p](hud-steering-high-1280x720.png) / [1080p](hud-steering-high-1920x1080.png)
- [低速時 720p](hud-steering-low-1280x720.png) / [1080p](hud-steering-low-1920x1080.png)

画像は実際のHUDビルダーを既存の参照背景に重ねた表示検証用プレビューで、実コースの走行画面ではない。

操舵・ドリフト・Modern UIの既存検証も通過。通信・ゲーム進行の既存オフラインテストは51件通過した。検証用Unityでは既存の `UnityEditor.Search.SearchDatabase` 初期索引例外が出たが、ゲーム側の試験例外や失敗はなかった。

描画用LODの生成は検証中のみ省略し、元のLOD0と衝突形状を使った。描画用の設定変更は成果物に含めない。

再実行方法と調整値は [Documentation/Steering.md](../../Documentation/Steering.md) を参照。これは自動入力での計算・物理・コース追従の検証であり、実機IMU付きハンドルを人が握った体感評価は未実施。
