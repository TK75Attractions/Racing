# CPU2台のレース検証

Unity 6000.3.9f1 / Apple M1。2026-10-14に検証。設定と再実行方法は`Documentation/NpcRace.md`。

- `report.json`: SampleSceneの実車4台をペダル・操舵で2周試走した記録。人間アイテムは停止し、通常走行を評価。CPU2台の少なくとも1周、離陸・着地、抜き合い、人間の完走待ち、4台結果、次の組の再生成を確認。最後の人間が終了した時点で未完走CPUをDNFとするため、CPU全台の規定周回完走を待つ試験ではない。
- `recovery-report.json`: 故障注入による復帰試験。保存点は実走で取得し、路面下への落下・他車による占有・カメラの可視性を検証用に変更。占有時・画面内の復帰拒否、画面外への復帰、周回・チェックポイント保持、再走行、自動復帰の発動、人間との接触後の衝突抑止・解除を確認。
- `performance.txt`: 同一実行内で2台→4台→2台の比較。両視点を1920×1080に出力し、4台の中心が両視点の視野内にあることを確認。静止配置、VSyncなし、Editorでの診断値。初回シェーダー準備後に4秒・60フレームを待ち、6秒・120フレーム以上を測定。
- `four-cars-p1.png` / `four-cars-p2.png`: 測定時の両視点。4台が見えるように検証時のみ道路サンプルへ配置する。通常レースでこの配置・移動は使わない。

EditModeの37件、既存のRaceCourseValidation・ModernUIValidation・MiniMapValidation、4台のCPU優勝／人間4位の結果表示、ネイティブのCPU2台を含む音声ミキサーテストも実行する。

描画測定は本番の入力遅延の合格証明ではない。実機の両Display、シリアル入力、両音声機器を接続して操作遅延・音切れを測り、初見参加者が抜き合いを認識できるか、接触後に再走行できるかを確認する。保存したバッチ画像ではHUDの合成を確認できていない。HUDの更新は有効だが、測定値は車両描画の比較用として扱う。HUDの構築・順位・ミニマップ・結果のバインディングは別の検証で確認する。HUDを含む本番画面構成の負荷・操作遅延は実機で判定する。
