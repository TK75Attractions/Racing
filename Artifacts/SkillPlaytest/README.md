# レベル別テストプレイと改善記録

Unity 6000.3.9f1 の SampleScene を実際に Play Mode で動かし、車両の物理、アイテム、CPU、レース終了処理を通して試走した。
**人間による試遊ではなく、レベル別のペダル・ハンドル入力を生成する自動プレイヤーによる検証**。実機ハンドルの操作感、音の聞こえ方、案内を人間が理解できるかは別途試遊が必要。

## 条件と証拠

- 1コース 1,829.064 m、設定2周、人間役2台＋製品版CPU2台。固定物理ステップ 0.02秒。
- 初心者：目標12m/s、判断間隔0.35秒、操舵誤差±3度、ジャンプを事前には予測しない。
- 慎重派：16〜18m/s、0.35秒、±1.5度。中級者：20〜24m/s、0.14秒、±0.3度。
- 上級者：27〜28m/s、0.06秒、±0.3度。攻めるプレイヤー：32m/s、0.18秒、±4度、操舵量1.25倍。
- 上級・中級はジャンプ手前で加速する。曲がり角では減速。速度は入力制御の目標値で、車の速度を書き換えていない。中心線を参照できるため、道迷いや画面からのコース認識を再現しておらず、実際の初心者より有利な部分がある。
- 途中停止はP2の目標速度を物理時刻45〜57秒の12秒間ゼロにする。切断は45〜50秒の5秒間、入力ソースの接続状態を切る。運営終了は20秒で通常の `ShowResult()` を実行する。
- 準備画面は試走開始処理から省略。位置・速度・周回・順位・結果をテストプレイヤーが書き換えることはない。実際のゲーム側の復帰処理は動作する。
- 変更後は、公開されている「ペダルを離す」案内に0.35秒後に反応して0.3秒間ニュートラルにする。初心者・慎重派はジャンプの画面案内に0.35秒後に反応し、目標24m/sで助走する。この理解・反応を仮定したモデルであり、実際の初心者が案内を理解した証明ではない。
- 乱数シードは固定したが、物理演算、描画とのタイミング、CPU判断に使う全体時刻は決定論的ではない。1条件1レースの比較であり、統計的な優劣は主張しない。
- CSV の `time` は積算物理時間、結果の `seconds` / `finishTime` は製品のレース時計。加速実行時は完全一致しない。`environment-contact` には路面への着地も含むので、衝突事故数とは呼ばない。

各フォルダに全体の `report.json`、車別 `summary.csv`、進捗グラフ `progress.svg`、各レースの `trace.csv` と `events.csv` を保存。結果を強制して成立させたデータではない。

## 変更前に実際に再現した問題

変更前の基準リビジョンは `1c14761`。6条件を完了し、記録中のゲーム実行エラーは0件だった。

| 問題 | 試走の証拠 | 対応 |
|---|---|---|
| 1. グリッドから最初のライン通過を1周と誤判定 | 全車が6.22〜13.12秒で「1周完了」。2周設定で実質1周しか走っていない | 初回のスタートライン通過と、1周を走り切った通過を区別 |
| 2. 運営が途中終了するとP1を勝手に完走扱い | operator-stopで約21.8秒・1周未満のP1が完走結果になる | 未完走の参加者は全員DNFとして確定 |
| 3. 初心者がコース外から自力で戻れない | novice-expertのP1が11.0秒コース外、40秒猶予でDNF | 路外・転倒・動けない状態を検出して安全な路面へ復帰 |
| 4. 停止後の復帰に時間がかかり、あと少しでも終了 | stop-rejoinのP2は17.2秒コース外、終了時は残り約225.5m | 残距離とそれまでのペースから猶予を40〜180秒に調整。全体360秒上限は維持 |
| 5. CPUが初心者を待つために停止する | novice-expertのCPU2が連続27.3秒停止 | 追走時の目標速度に下限を設定。直前の車への安全な減速は維持 |
| 6. CPUが路外に残り続ける | stop-rejoinのCPU2が114.7秒路外、復帰0回 | 初期安全位置も保存し、長時間の路外滞留では画面内判定による復帰禁止を解除 |
| 7. CPUが復帰しても繰り返し失敗 | stop-rejoinのCPU1が58.1秒路外、復帰5回 | 復帰直後の後退を解除し、安全位置・路面の検出を見直す |
| 8. 入力切断中も惰性で進み、再接続した瞬間に加速 | disconnect-rejoinでP2は切断約1秒後も11.25m/s、再接続約0.1秒後にペダル1.0 | 接地時に制動し、再接続は一度ペダルを離すまで入力を保留 |

## コード確認・個別検証で追加して直した点

以下は自然なレース中に全てを再現したという意味ではない。問題となる状態を専用フィクスチャで作り、製品の処理を呼んで確認した。

9. 復帰先が他車と重なる：中央と左右を調べ、すべて占有されていれば空くまで待つ。
10. リセットを押しっぱなしで何度も復帰する：押した瞬間を検出する。
11. 復帰後もアイテムの妨害が残る：妨害を解除し、2秒間は連続して被弾しない。
12. 復帰時にペダルを踏んだままで飛び出す：一度離してから再開する。
13. ゴールセンサー内への復帰で周回が増える：復帰直後の重なりを除外し、出てからの通過は通常どおり数える。
14. 接続切れ・入力保留・復帰待ちで何をすればよいか分からない：各プレイヤーのHUDに具体的な案内を追加。
15. DNFではどれだけ走れたか分からない：結果に完了周回数を表示。
16. ベストラップ未計測の内部上限値を表示してしまう：未設定の値はプレースホルダーにする。
17. 明るい選択ボタン上でホールド率が白く読みにくい：選択時の数値も濃い色に変更。
18. CPUの復帰先の上に別の物体があると路面があるのに失敗する：最初に当たったものだけで判断せず、路面の支持を確認。

19. 復帰先の助走距離不足：再走で発見して修正。
20. ジャンプに初めて近づく人への予告不足：45m手前から「まっすぐ加速」を表示。
21. 新しい日本語の一部が静的フォントにない：フォントを再生成し、案内文字の収録を自動検証。

## 再走で見つかった追加課題

安全位置がジャンプの踏切に近すぎると、復帰後に助走を取れず同じ場所で落ちる。最初の改善版の初心者条件で、約300物理秒時点でP1の復帰が63回、進捗約228mに留まることを確認した。この版を成功として扱わず、初心者条件の完了後に試走を中止した。`Iteration1` の第2条件は途中記録なので集計から除外する。最終版では踏切手前35m以内を安全復帰地点として新規保存せず、45m手前から画面で加速を案内する。

| operator-stop | 完走(1周) / DNF(1周) | DNF(0周) / DNF(0周) | 20.76秒 | 0.00秒 |

変更前の「2周完走」は初回ラインの誤カウントを含む。最終版では正規の2周になったため、時計の数値を速さの改善率として比較しない。

- 初心者条件：P1の路外時間は最終版0秒。CPU2の連続停止は27.3秒だった基準走行に対し、最終走行では0秒。初心者へのジャンプ案内に反応する入力モデルという条件付きの結果。
- 最も問題のあった停止条件：P2はDNFから2周完走へ。路外時間は17.2秒だった基準走行に対し最終走行では1.8秒。CPU2の路外滞在は114.7秒だった基準走行に対し最終走行では0秒。
- 切断条件：最終版では47.02物理秒でP2の水平速度0.001m/s。50.12秒では要求ペダル1.0でも停止を維持し、50.36秒にペダルを離す応答後に再発進。2周完走。
- 運営終了：最終版はP1/P2/CPU2台とも0周・DNF。P1を架空の完走者にしない。
- 初心者役は猶予180秒でも1周・進捗3259.5mでDNF。正規の2周をこの低速モデルで完走できたとは言わない。初心者向けの周回数・制限時間の別設定には検討余地がある。
- 停止時間の指標には意図した停止・切断中の安全停止も含む。そのため停止条件の `maxStall` 増加をそのまま不具合の増加とは解釈しない。

`After/verification.json`：6条件の正常終了、全体締切、実際の移動を伴う初回周回、運営終了のDNF、切断時の入力中立、再接続時のペダル解放応答など、62チェックに合格。記録中のゲーム例外0件。

基準走行の製品リビジョン：`1c14761`。変更後6条件のリビジョン：`c86376c`。その後、手動リセット保持とCPUの反復復帰を追加修正した。通常速度での追加記録は `Realtime`（製品修正 `8a0bb60` を含む）、個別検証は `NpcRecovery` を参照。

## 検証の注意

初回ラインの誤カウントを修正したため、変更後は正しく2周する。変更前後の所要時間・接触回数をそのまま改善率として比較することはできない。プレイヤーの能力を上げたとの主張もしない。

Unity起動時に既存の `UnityEditor.Search` の `ArgumentOutOfRangeException` が記録されることがある。試走エージェント開始前のエディター側の例外であり、記録中のゲーム例外と区別した。

### 表示確認の範囲

バッチ実行時のJPEGは3Dカメラ映像を保存できるが、画面のHUDは含まれない。これをUIの完成スクリーンショットとして扱わない。HUDの案内内容・有効状態は同時保存のテキスト診断およびEditor検証、フォントの文字収録検証で確認した。通常のウィンドウと実機の複数モニターでの見え方は人による確認が残る。


### 通常速度で見つかった追加修正

最初の1倍速70秒観測 (`RealtimeBeforeBackoff`) では、停止条件のCPU2が同一地点へ7回復帰し、路外時間が18.0秒となった。加速実行だけで解消と判断せず、同じ保存地点で復帰に失敗する場合は20mずつ、最大80mまで手前の路面を候補にする処理を追加した。空きと路面を確認し、同じ周回内で、復帰前より進捗が進まないことも確認してから戻す。

CPU復帰の故障注入検証では、接触保護の開始までは通ったが解除の検証が失敗した。テスト車を走路上へ戻すと再接触する余地があるため、解除テストでは明確に離した位置へ移してから、保護が期限どおり解除されるかを確認する。失敗時の結果も `NpcRecoveryBeforeSeparation` に保存した。


### 通常速度の再確認結果

最後の `Realtime` は時間倍率1、停止・再接続の各70物理秒を観測した。両条件とも記録完了、記録中のゲーム例外0件。観測窓で終了しているため、完走やDNFの集計には使わない。

## 最終検証

- `NpcRecovery/report.json`：復帰専用の故障注入検証9項目に合格。全候補が他車で埋まっているときの拒否、見えている間の短期復帰の拒否、見えていない場所での復帰、周回状態の保持、反復失敗時の後退、復帰後の走行、自動復帰、接触保護の開始・解除を確認した。通常走行の周回・追い越し・結果・リトライ項目はこのモードでは実施しないため、JSONでは初期値のまま。
- `final-validation.txt`：最新のEditor検証がすべて成功。手動リセットを押しっぱなしにしても、復帰時の入力中立を「ボタンを離した」と誤解して再実行しないことも確認した。中央が占有されている場合の左右候補、全候補占有時の待機も確認。
- `core-tests.txt` と `Artifacts/Rgp/test-results.xml`：レースセッション・入力プロトコル等の56テストに合格。
- `After/verification.json`：変更後6条件の走行記録に対する62チェックに合格。
- `Realtime/report.json`：通常速度の最終2区間が完了し、記録中のゲーム例外0件。

後退候補の導入後は、問題が出た通常速度の停止・再接続条件と故障注入検証を再実行した。6条件全体を再度繰り返したわけではない。実機ハンドル・ペダル、実際の初心者による案内の理解、実機の複数モニターでの視認性は今回の自動試走には含めない。
