# 管理画面のプレイ集計（2026-11-01）

「プレイ集計」ページに本日の人数・条件別ランキング・日別の人数と横棒を追加した。30日／90日／全履歴の切り替え、ランキングの20件ずつの表示、10秒ごとの更新、通信切断時の最終集計表示に対応する。常駐サービスが履歴を読み取るため、Unityの接続・起動状態から独立して閲覧できる。

ゲーム側では人間プレイヤーの開始を、完走ランキングとは別のPlays日別ファイルに記録する。CPU・自動運転・一定ペダル試験・自動バッチは除外する。レースIDと席番号で重複を防ぎ、未完走も保存する。開始日をまたいだ完走を次の日の人数に二重加算しない。過去の開始履歴がない部分は保存済み完走記録を用い、復元できない未完走人数は推定しない。

## 検証

- `Tools/Validate-PlayStatistics.sh`: 本番.NET 10ビルドは警告0・エラー0。集計テストは空履歴、日付またぎ、開始と完走の重複、未完走、再読み込み、コース別の順位、同順位、日付切り替え、バックアップ復旧、壊れた型と元ファイルの保持を通過。
- ロジック: 206件成功・失敗0。P1/P2の開始、再プレイと重複、無効な席・識別子を検証。
- 管理画面: 84件成功・失敗0・任意診断ブラウザーテスト1件スキップ。独立したページ、本日の値・順位・横棒、Unity切断後の閲覧、履歴の期間選択、空表示・警告、20件ずつの追加、HTMLを含む文字列のテキスト表示、更新失敗時の最終データ保持を確認。
- 実Unity: 複製した別プロジェクトで `PlayStatisticsValidation.Run` が成功。実際のJsonUtilityでの開始保存、P1/P2、再プレイ／再起動での重複防止、日付またぎ、試験の除外、周回メタデータ、バックアップ、破損時の保持を検証した。検証は一時フォルダーだけを使用し、本番の履歴は変更していない。
- 配信中のAPI: 本日と10日分の保存済み履歴を返し、警告なし。本日の記録が空の場合を確認。配信HTMLに新しいページとナビゲーションがあることを確認。
- ブラウザー: 実際の管理画面をUnity未接続の状態で開き、本日の集計と10日分の履歴を確認。1280px幅でdocument.scrollWidthも1280px、横へのはみ出しなし。人数・表・横棒の見た目を確認した。ランキングにデータがある表示は合成データでのUIテストで確認した。

Windowsでの実行と、Race本体の新たなPlayerフルビルド・起動検証は行っていない。新しい開始記録はRace本体への反映が必要。詳細は [PlayStatistics](../../Documentation/PlayStatistics.md)。

## このPCへの反映

検証済みの.NETサービスとページを `dotnet run --no-build --project DashboardRelay.csproj -- --update-service` で反映し、接続先・権限・通知登録は保持した。管理画面を再読み込みすると「プレイ集計」から過去分も閲覧できる。稼働中のRaceは停止せず、履歴データの移行・書き換えはしていない。mainへのマージ・pushは行っていない。
