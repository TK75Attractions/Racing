# タイトル表示後の入力準備待ち（2026-10-20）

ハードウェアのGET_STATUSで正常・校正済みを確認しても、`RgpHostSession.PrepareHardwareAutomatically`がすべての未応答コマンドを待っていた。PING等が遅れると1秒単位の再送待ちが角度準備にも波及する。また、準備中の状態確認も通常走行と同じ2秒間隔だった。

準備の前提をセッション確立・センサー正常・機器状態の確認に限定し、関係のない応答待ちがあっても必要な校正／角度合わせを進める。各操作1回と同一SEQ再送の制限は維持する。準備中の状態照会は250ms、READY後は従来の2秒間隔とした。READYと新しい有効TELを受け取るまでは入力を有効にしない。

シリアルモニターへStateとFirst usable input（通信開始から最初の有効入力までのms、待機中は-1）を追加した。同じ時刻はシリアルジャーナルのINPUT_READYにも記録する。実機の校正所要時間とゲーム側の待ち時間を切り分けられる。

新しい回帰テストは、PING／設定照会の応答が遅れても、正常なGET_STATUSを受信した次の更新でANGLE_ZEROを送ることを確認する。修正前はこのテストで失敗、修正後は既存を含む98件すべて通過。本番受信処理を使う実PTY検査の接続、両者停止、通信復帰、CRC拒否、分割、描画停止、古いキューとペダル解除待ちも通過した。`validation.txt`に主要出力を保存した。

実機接続での所要時間は未計測。ESP32自身の校正が必要な時間は省略しない。
