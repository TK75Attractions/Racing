# P1 ESP32ハンドル＋代替ペダル（2026-10-20）

## 確認した条件

Unity 6000.3.9f1、本番の`InputManager`、RGP受信処理、`PlayerDriveInputGate`、`car2.prefab`のタイヤ物理・姿勢制御・PhysXを使用した。実PTYへ100Hz設定でP1ハンドル78度・アクセル0・ブレーキ0、P2ハンドル-39度・アクセル0.5・ブレーキ0を送信。Steering Divisorは6.5で、ゲーム側のハンドル値はP1=12、P2=-6になる。

- 通常入力の保持、キーボードW/SとESP32ハンドルの合成、キーボードA/DとESP32ペダルの不使用。
- P2のシリアル入力を変更しないこと、キーボード専用起動からの途中切替ではP2のキーボードを変更しないこと。
- 常時入力の0〜1制限、NaN拒否、準備・練習・結果でのキーボード操作、ポーズ時の入力停止。
- モードを変えても同じアダプターを維持し、既存の入力ゲートへ解放待ちを設定すること。
- 切断で常時入力も停止し、再接続後に勝手に加速せず、Sによる解放を待つこと。WとSを同時に押してもSで常時入力を解除できること。
- 実ポートの閉鎖時もP1の常時入力が0になり、未接続となること。
- キーボード専用起動では最初にシリアルを開かず、ハンドルテストのライブ有効化で開くこと。Normalで元のキーボードへ戻ること。

接続状態の再接続試験は同じアダプターに対して接続フラグを変える試験用入力で行った。実PTYではセッション確立・受信・切替・ポート閉鎖を確認した。実ESP32のUSB抜き差しと操作感は未確認。

## 本番車両の物理走行

試験用の平地へ本番車両を静止配置し、P1のハンドル12・常時ペダル65%を通常の入力ゲート経由で1.6秒入力した。以降の位置・姿勢・速度は直接設定しない。

移動距離16.84m、開始時からの車体向きの変化75.93度、終了速度18.36m/s。ESP32側のペダルが0のままでも代替ペダルで加速し、ESP32のハンドルで旋回することを確認した。停止した車を強制回転・移動させるテストではない。通常レース1周や人による操作感の評価とは区別する。

`validation.txt`に主要マーカーを保存。既存の純粋C#98件とUnityのP2切替・解放ゲート・ポーズ、操舵支援、着地・追走・チューブ・結果表示も回帰確認した。詳細操作と再実行は[説明書](../../Documentation/P1SteeringTest.md)を参照。

実行準備では、送信開始をUnityの読込完了に合わせ、PTYの未読バッファが起動待ち中に満杯にならないようにした。初期試行の送信器停止とUnityによるTemp削除はテスト手順の問題で、製品の入力不具合の証拠には使用していない。
