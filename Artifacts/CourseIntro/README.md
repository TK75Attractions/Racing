# レース前のコース俯瞰（2026-10-21）

[導入から発進までの動画（16秒・無音）](Final/course-intro.mp4)

実際のSampleSceneとP1カメラを使い、上空約260m → 校舎正面約28m → 各プレイヤーの車両後方 → 3秒カウントダウン → 発進を収録した。約9秒の導入で、P1/P2は校舎を同時に見る。走行HUDは導入中だけ非表示にし、コース名とレターボックスを表示する。F8の `Pre-race drone course preview` で省略できる。

動画は24fps・1280×720のオフラインゲーム時計収録。末尾の観測終了後の惰性走行を含めず、発進後約4秒までの連続した16秒を保存した。フルの19.083秒は `Logs/CourseIntro/Final/human-fast-control-7102/gameplay-p1.mp4`。動画・通常チェックはab59698を基点に本機能を適用した作業ツリーで収録。後の中断・再開時のUI破棄修正は通常再生の映像を変えない。準備画面はテスト起動で省略し、以降は製品と同じ開始フローを使う。

## 確認結果

- 通常再生：8.999995秒まで観測。導入中のレース時計0、車両の平面移動0。走行許可なし。両画面の位置同期、HUD非表示、導入後の全3秒カウントダウン、カメラ・HUD・背景の削除を確認。`Final/course-intro-checks.json`。
- 途中OFF：2.50秒時点でF8相当のOFFを適用。通常のカメラ・HUDへ戻り、3秒カウントダウン後に発進。`Checks/off.json`。
- 中断・再開：2.5秒後にコンポーネントを無効化し、同じフレームで有効化して再開始。UI名の再利用が遅延Destroyの対象へ結び付かないよう、旧UIをCanvasから先に切り離す。再生完了・各画面の正しい車載カメラへの復帰・一時オブジェクト消去を確認。`Checks/restart.json`。
- 3条件とも走行中の例外0。新しいスイッチの既定ONも含む単体テスト108件成功（`core-tests.xml`）。観測窓5秒／1秒の試験であり、完走テストとは数えない。
- 空から地面モデルの矩形の端が見えないよう、紹介中だけ既存Materialの背景Planeを表示する。Colliderを無効化し、導入の終了・中断で削除する。走行時のコース・物理や保存済みMaterialは変更しない。

初回の実走確認で見つけたHUD初期化（Unityのnative nullの判定、同じUI名による二重Image生成）も修正し、上記3条件で再確認した。
