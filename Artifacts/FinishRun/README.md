# ゴール後の短い自動走行（2026-10-20）

以前は`HandleCarFinished`が人間車を`FreezePlayer`で直ちに停止・固定し、CPUも`SetDriving(false)`で速度をゼロにしていた。

完走時に`FinishRunController`へ入力を引き継ぎ、現在の位置・速度を保ったまま約3.5秒の自動走行を行う。道路と実接地を観測して操舵・ペダルを決め、目標速度を滑らかに下げる。通常の車両物理で進み、最後の人間の完走後のGoal状態でも、この車の駆動とエンジン音を許可する。完走車同士・未完走車との衝突を無効にし、道路への接地は保つ。アイテム・加速パッドの追加取得を防ぎ、終了後は車体を固定する。

F8の`Short winning run after finish`は既定ON。途中OFFなら即停止し、再ONでやり直さない。事前OFFなら従来の即時停止。DNFに自動走行は付けない。公式結果はゴール時点のままで、既存のゴール演出時間も延長しない。

## 実走確認

Unity 6000.3.9f1、実SampleScene、Experience 1周、アイテムなし、3倍速（固定物理刻み20ms）。P1は車体とコースを観測して操舵・ペダルを決めるボット、P2は製品の自動運転、CPUは通常のCPU制御を使う。レース中の位置・速度・周回・結果の直接設定は行わない。ゴールイベントとその後の車体を観測した。

| 条件 | 確認結果 |
|---|---|
| ON | P1・P2・CPU2のゴール直後の速度32.33／38.24／36.53m/sを維持。約3.52秒の物理走行で、ゴール位置からの距離52.66／54.45／53.25m。その後停止。最後の人間のGoal状態を含め走行・エンジン有効を確認 |
| 走行中OFF | 最初の完走車が走行を始めた後にOFF。反映時点で停止し、以後の完走車は即時停止 |
| 完走前OFF | P1・P2・CPU2台の全完走車が従来どおり即時停止 |
| 後続車への影響 | ON時の完走車と他車の全Collider組が非接触になっていることを確認。完走後の公式タイム・順位が変わらないことを継続確認 |
| DNF | ON／途中OFFの試走ではCPU1が人間2台の完走によるレース終了時点で未完走。DNFとして固定され、自動走行が付かないことを確認。全車完走した試走としては数えない |

`report.json`は3条件の全完走イベント、ゴール直後の速度、ゴール位置からの距離、物理更新による継続時間、Goal中の走行有無を保存する。indexはP1=0、P2=1、CPU1=2、CPU2=3。各条件のタイムは同一性を検証した結果であり、ON/OFFの速さの改善率を算出する試験ではない。

純粋C#98テストと、P2入力切替／解放ゲート／ポーズ、操舵支援、着地、追走、チューブ、結果の既存Unity検証も通過。主要マーカーは`validation.txt`。Unity起動時の既知のSearch索引例外は走行検証と区別する。実ハンドルでの感触と実音声出力は別途確認が必要。

再実行：

```sh
RACING_FINISH_RUN_OUTPUT=/private/tmp/racing-finish-run \
  /Applications/Unity/Hub/Editor/6000.3.9f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -projectPath "$PWD" -executeMethod FinishRunValidation.Run \
  -logFile /private/tmp/racing-finish-run.log
```

検証終了時に自動終了するため`-quit`は付けない。
