# 運営・描画・カメラ修正（2026-10-29）

## 原因と変更

- 管理画面の画像APIは、Unityメインスレッドでゲーム用カメラすべての出力先を640×360に変更し、ワールドとUIを再描画した後、`ReadPixels`でGPU完了を待っていた。さらにCanvasを一時的にWorldSpaceへ変更していた。この取得を約2秒ごと、閲覧者ごとに繰り返すため、処理落ちと表示サイズ・Canvas再構築によるちらつきの原因になる。HTTPの画像APIは、通常のUI描画完了時の画像コピー（ネイティブ画面のP1はフレーム終了後のScreenCapture）とAsyncGPUReadbackへ変更。同じプレイヤーの同時要求をまとめ、1秒以内の画像を共有する。従来の同期キャプチャはEditorの撮影用途に残す。
- HTTP応答の書き込みをワーカースレッドへ移し、遅いブラウザーの読み取りでゲームのフレームが止まらないようにした。設定のJSON比較を毎フレームから状態配信時（10Hz）に減らし、WebSocket画面のDOM描画も30Hzから10Hzへ制限した。
- 壁登りでは車体の上方向から取る遮蔽判定始点と、ワールドの上方向へ配置するカメラの位置が一致していなかった。さらに急傾斜の高さ補正が垂直に近い法線で増幅されていた。接地面の内側にカメラと遮蔽判定始点を揃え、急傾斜を通常坂の高さ補正から除外し、高さフィルターの遅れも40cmに制限した。水平線と通常の坂道追従、別障害物に対する遮蔽判定は維持。
- 結果画面は「次へ」1個。ハンドルでの選択変更は廃止し、旧「タイトルへ」と同じ各プレイヤー個別のエンディング・タイトル復帰へ接続。ペダルを離してから長押しする条件を維持。管理者APIの再挑戦は維持。
- トンネル模様は夜景統合前のmain（`b999f6c^2`）の二重レール・矢印・光の流れと強度2.4へ復帰。新しい距離メタデータ、滑らかな壁メッシュ、衝突判定、入口フレームは維持。
- 遠隔操作後の入力復帰は、入力が実際に読まれるgetterだけでペダル解放を判定していた。操作中に離した入力が記録されず、タイトル待機中などの解放も見逃せた。実機の入力を毎更新で観測し、遠隔操作中の解放も復帰条件へ反映。ずっと踏み続けたペダルは一度離すまで抑止し、抑止で生成した中立値を物理的な解放通知として扱わない。
