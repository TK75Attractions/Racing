# 試合終了後の更新とクイックレース（2026-10-31）

## 変更

ビルド成功後に試合が継続している場合は終了を待ち、その間も更新をキャンセルできる。タイトル・結果画面に進んだら、状態と設定の変更番号を使ってメンテナンスを要求し、次の試合が始まらないことを確認してからアプリ切り替えを確定する。片方だけの完走結果表示、練習・カウントダウン・ゴール演出、ゲームAPIが応答しないままRaceプロセスがある場合は切り替えない。

キャンセルと切り替えは従来の排他的なdecisionファイルで決定する。更新側が有効にしたメンテナンスは、キャンセル／引き継ぎ失敗時に同じゲームセッションだけへ解除を要求する。常駐サービス再起動後も待機を再開する。ゲーム自身が起動した更新については生きているゲーム側の解放処理と競合せず、そのゲームが終了済みなら常駐サービスが引き継ぐ。

通常（練習あり・2周）とクイック（練習なし・1周）を管理画面とF8から選べる。クイックは両者の開始操作後、練習・説明・コース紹介を省略してカウントダウンへ進む。最初の開始操作から試合ルールを固定し、以降の選択は次の試合へ予約する。ゲーム種類の選択はアプリ終了まで保持し、順位・本日のタイムは周回数とゲーム種類を含む集計枠へ記録する。

## 反映

常駐管理画面を `Tools/DashboardRelay` の `dotnet run --project DashboardRelay.csproj -- --update-service` で更新して再読み込みする。ゲーム種類の選択には新しいRace本体も必要。管理画面の「最新mainでビルド・起動」はorigin/mainを使うため、作業ブランチの修正を含めるにはmainへマージ・pushしてから実行する。詳細は [OperatorUpdate](../../Documentation/OperatorUpdate.md)。この作業ではpush・mainへのマージ・稼働中アプリの入れ替えは行っていない。
