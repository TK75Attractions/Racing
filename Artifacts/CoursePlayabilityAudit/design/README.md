## 再現方法と数値の意味

`python Artifacts/CoursePlayabilityAudit/design/verify_design.py`（Python標準ライブラリのみ）で `report.json` と `predicted-geometry.csv` を再生成する。動作確認には `C:/msys64/clangarm64/bin/python.exe` を使用した。既定の `python` はこの環境では標準ライブラリの初期化に失敗する。

`predict.py` は RaceCourse.BuildCenterPath と RaceCourseLineSmoothing.Apply の処理を移植している。楕円のcosによる距離パラメータ、SmoothStepの幅、sourceの区間所有権、倍精度積分、閉路、チューブ制限の遷移、ジャンプ端の縮む窓を含む。既存のチューブ点は読み取り専用のSampleSceneから採取して `source-waypoints.json` に固定し、新しい点と幅配列は実際のSchoolMapCourseSetupから読み取る。点数や幅を前任案に固定していない。元のgeometry.csvに対する位置の最大誤差を5mm未満として検証し、幅の再現誤差も記録する。入力ファイルと予測スクリプトのSHA-256はreport.jsonに記録する。

OBJ三角形を道路の全連続区間へクリップし、路面勾配を補正した鉛直0〜2.5m帯で左右の道路端までの符号付き距離を求める。負なら侵入。道路の実際の隣接平均接線による縁と区間法線の差を保守的に包み、縦方向にもその誤差を広げ、高さへ3mmのガードを加えている。単なる頂点・固定高さの点サンプリングではない。対象を前任の矩形範囲から拡張し、**チューブ内・路面のないジャンプを除く、片端でもY>2.9のすべての道路区間**（北・西側接続と着地後も含む）とした。既存床の切り抜き形状は通常刻みで別枠として報告する。壁離隔・方位・曲率・全周の幅変化率は通常1.5mと細分化0.25mの両方で合格を確認する。

曲率は隣接する路面区間の方位差を平均水平長で割った値。ジャンプの路面なし区間との接続は除外し、空中弦との接続角も別途報告する（今回の踏切では0.000001°未満）。40mは生成後の3D進捗距離で区切り、方位はXZへ投影して絶対変化量を合計する。0.5°以内の整列長は生成ポリラインの水平長を、端から連続して合格する完全な区間だけ合計する。

`road_edges` は `RaceCourse.BuildOffsetPaths` の隣接サンプル接線と閉路の継ぎ目を、`road_triangles` は `RaceCourseRoad.Build` / `AddTriangle` の頂点順、路面なし区間、退化三角形の除外を移植している。チューブを含む全周のRoad Surfaceの各外積Yが正であることを確認し、踏切・着地近傍の反転数も個別に記録する。平面から法線を推定するだけの検査ではない。ペイント・肩・バリアは別メッシュのため対象外。倍精度予測に加えて頂点をfloat32へ丸めた感度確認も行うが、Unityの全演算をビット一致で再現するものではない。曲率の余裕も小さいため、最終的な生成メッシュと走行はリード側のUnity検証が必要。

OBJは既存のColliderのみを記録しており、Rendererの独立した出力ではない。壁のFBX共通形状を見た目の離隔の代理として扱う。床のOBJは旧走路で既に切り抜かれているので、新しいFBX再切り抜きの見た目をこの資料だけで保証できない。上の高さは旧経路との比較であり、床からの全幅支持の保証ではない。校舎の壁をColliderだけ切り取る別担当の処理に、今回の壁回避は依存していない。

コンパイルは `powershell -File Artifacts/CoursePlayabilityAudit/design/compile.ps1`。Unityを起動せずEditor/Data/NetCoreRuntime/dotnet.exeからDotNetSdkRoslyn/csc.dllを実行する。既存DLLを参照した当該ファイル単体の確認であり、他担当の変更を含むUnityプロジェクト全体の再コンパイルではない。

## リード側の適用・再配置

1. `SchoolMapCourseSetup.Run`。末尾の `TubeCoursePreparation.Run` が床の表示・Collider、道路・バリア、スタートを含むチェックポイント、ゴール、Item Box Row、Charge Crystalを再生成／道路へ投影する。続いてTubeSpeedPatternSetup、TubeCourseValidationも自動実行する。
2. `NeonRaceMarkersBuilder.PlaceFinishGate` → シーン保存。ゲートの幅も更新する。BuildはPrefab作成だけなので再配置にならない。独立したスタートラインがあれば更新後のStartに合わせる。
3. `NightEnnichiVisualBuilder.Run`。保存済みシーンが前提。行灯・ランドマーク・RaceTubeEnvironmentTransitionのベイク距離を更新する。
4. 方向Prop／手置きライトは配置ツールで変更区間を修正し保存する。CourseDirectionPropsBuilder.BuildはPrefab生成のみで、再配置メニューはない。
5. ベイク済み反射を使う場合、CourseReflectionProbeBuilder.Run → Bake。道路・バリア・実行時近景マーカーは道路変更に追従する。
6. Probe / Auditを再実行し、床と校舎の表示、スタート・ゲート、踏切のバリアと空中軌道、着地後、装飾を実測・実走確認する。
