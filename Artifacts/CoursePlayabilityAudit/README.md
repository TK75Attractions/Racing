# コースのプレイしにくさ監査（SampleScene）

2026-10-21 日本時間。Unity 6000.3.9f1。調査のみで、シーンやゲームの挙動は変更していない。

**距離の表し方:** 「スタートから ◯m」は、スタートグリッドから**レースの進行方向**に測った距離（1 周 1,904m）。ログや CSV の `progress_m` はコース内部の距離で、進行方向と逆向きになっている。換算式は `スタートから = (58.5 − progress_m) mod 1904.2`。

## 一番の原因

青いバリアは、走路の端から一律で**約 4.8m 外側**に自動生成されている（全周 3,809 地点で左右とも 4.56〜5.31m）。その内側、つまり走路と路肩に、**校舎モデル `1016こうしゃ` の MeshCollider が有効なまま**入り込んでいる。走路と重なる部分を無効にする処理は、木の枝・葉にしか入っていない。このため、バリアより手前で校舎の壁・柱・部品に当たる。

### 問題が見つからなかったもの
- 縁日の灯籠（`NightEnnichi/Lanterns`）、ネオンのマーカー、方向表示の Prop は、走路にも路肩にも入っていない。
- バリアの欠け: 全周で左右とも 0 地点。
- 自動走行 1 周（2 台、中央 ±2m の車線）: 障害物との接触 0、コースアウト 0、大きな減速 0。ただし中央付近しか走らないので、上の #1・#2・#5・#6 のような端の障害は、この試走では拾えない。

## 計測の方法と限界
- `findings.md` / `findings.csv` は `Assets/Editor/CoursePlayabilityAudit.cs`（Codex が作成）の出力。丸めた後の実際の走行線を 0.5m ごとにたどり、当たり判定の三角形を断面で切り出して、走路への食い込み量を測った。続けて自動走行を 1 周行った。
- `probe.md` は `Assets/Editor/CoursePlayabilityProbe.cs` の出力。車の高さ 0.3/0.8/1.5/2.2m で、横向き（走路の端からバリアまで）・前向き・上向き・下向きに光線を当て、床と壁を区別した。上の #1〜#7 と #9 はこちらで確定させた。
- `findings.md` の「チューブ出入口の路面未検出」は計測側の不具合（全地点で路面を拾えていない）なので、一覧から外した。
- 再実行するには、Unity を閉じてから次を実行する（`-nographics` を付けるとプレイモードに入る段階で落ちる）。
  - `Unity.exe -batchmode -projectPath <repo> -executeMethod CoursePlayabilityProbe.Run -quit`
  - `Unity.exe -batchmode -projectPath <repo> -executeMethod CoursePlayabilityAudit.Run`（`-quit` は付けない。終われば自動で閉じる）
