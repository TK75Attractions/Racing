# ディスプレイ切断・再接続（2026-10-31）

macOS / MetalのP1・P2・観戦用ネイティブウィンドウを対象に、切断した画面のウィンドウだけを隠し、同じ画面が復帰したら全画面へ戻す。残った画面のプレイヤー割り当て・全画面表示・フォーカスは維持する。初回の2画面割り当てを永続UUIDで記憶し、接続画面数が減ったときに両ウィンドウをデスクトップ表示へ戻していた処理を置き換えた。

ウィンドウは閉じたり作り直したりせず、ゲームの状態も初期化しない。非表示中もゲーム進行は続く。P2・観戦用出力が非表示の場合はMetalのdrawableを取得せず、切断前にキューへ入った描画要求でも現在の可視状態を再確認する。消えた画面の描画待ちで他の表示を止めない。

## 検証

`sh Native~/RaceWindows/test.sh` の結果は [native-tests.txt](native-tests.txt)。既存の起動配置12ケース・観戦画面選択・AppKitウィンドウ形式の回帰試験に加え、以下を検証した。

- P1だけ、P2だけ、両方の切断と、片側から順に再接続するケース。
- 100回の切断・再接続、画面の列挙順・座標・数値ID・解像度の変更。
- 接続されていないプレイヤーを、無関係な新しい画面へ移さないこと。
- ミラーリング、無効な画面サイズ、曖昧な重複UUID。
- 本番のAppKit配置処理で、切断したウィンドウだけをorderOutし、再接続で元の割り当てへorderFrontすること。
- OSが通知より先にウィンドウを他画面へ移動・非表示にしていた場合も、保持した割り当てと可視状態で復帰すること。
- 接続を維持している側のframe更新と、P1のmakeKeyWindowが増えないこと。
- 観戦画面だけの切断・復帰、手動配置・手動で閉じた状態の維持。
- 明示的な通常ウィンドウモードへの切り替えで元のウィンドウ形式へ戻ること。

画面構成はテストデータ、本番のウィンドウ操作は非表示のAppKitテストウィンドウで検証した。テスト用ウィンドウは実際のデスクトップには表示しない。物理モニターのケーブルを抜き差しする検証や、Windowsでの実行は行っていない。

`sh Native~/RaceWindows/build-macos.sh` で同梱プラグインをarm64/x86_64のUniversal dylibとして更新した。新しいColorSync依存はOS標準フレームワーク。既存の起動中アプリへは後付けされないため、UnityでMacアプリを再ビルドして起動し直す必要がある。
